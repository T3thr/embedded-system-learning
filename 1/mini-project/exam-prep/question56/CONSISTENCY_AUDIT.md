# ผลตรวจความสอดคล้องสำหรับข้อ 56

ตรวจวันที่ 28 กันยายน 2026 ชุดเตรียมสอบนี้ไม่ได้แก้ไขไฟล์ใน submission

**ข้อสรุป:** ตารางพอร์ตและค่า P1 ของต้นฉบับถูกต้อง และเฟิร์มแวร์ต้นฉบับประกอบด้วย EdSim51 2.1.39 ได้ แต่ลอจิกยังไม่ตรงเงื่อนไขความปลอดภัยทั้งหมด จึงไม่ควรนำผลการประกอบสำเร็จไปเรียกว่าผ่านการทดสอบระบบ

## จุดที่พบในเฟิร์มแวร์ต้นทาง

1. **การรับปุ่มปิดขึ้นกับจังหวะลูป** ใน OPEN_HOLD บรรทัด 164–174 และ SAFETY_HOLD บรรทัด 312–322 เมื่ออ่านว่าปุ่มเป็น LOW จะล้าง CLOSE_ARMED ก่อนตรวจรับการกด จึงไม่รับการกดค้างอย่างเชื่อถือได้ จะมีโอกาสรับได้เฉพาะเมื่ออินพุตเปลี่ยนระหว่างจุดอ่านในลูป นอกจากนี้การตั้ง armed หลังเห็น HIGH ไม่มีการรอให้ปล่อยคงที่ 20 ms
2. **ลำแสงมีช่วงที่ไม่ได้อ่านประมาณ 20 ms** CLOSING เรียก DELAY_20MS แต่ลูปในซับรูทีนตรวจเฉพาะ TF0 การตัดแรงขับหลังตรวจพบถูกลำดับ แต่การตรวจพบเองถูกเลื่อนได้ ไม่ตรงคำอธิบายว่าตรวจซ้ำโดยไม่มีช่วงรอ 20 ms
3. **ลิมิต LO=LC=0 ไม่ใช่ global trip ในโค้ดเดิม** ตรวจความขัดแย้งตอนเริ่มเครื่อง แต่ไม่มีการตรวจซ้ำครบทุกสถานะ ตัวอย่างขณะ OPENING อาจตีความ LO=0 ว่าถึงปลายทาง ทั้งที่ LC ยังเป็น 0
4. **การอ่าน E-stop ระหว่าง Coast ห่างกันครั้งละหนึ่งช่วงหน่วง** และไม่มีการตรวจหลังช่วงหน่วงรอบสุดท้ายก่อนเข้า REOPENING แม้ NC1 จะตัด EN ได้โดยฮาร์ดแวร์ ซอฟต์แวร์ก็ยังต้องบันทึก FAULT และห้ามเริ่มขับใหม่ตามคำขอที่ค้างอยู่
5. **เวลาไทเมอร์ไม่รวม overhead** B1E0H ถูกต้องสำหรับนับ 20,000 machine cycles แต่เวลาเรียกและกลับจากซับรูทีนเพิ่มเข้ามา ประโยคว่า 250 รอบเป็นเส้นตายสูงสุด 5.00 s แบบพอดีจึงไม่ถูกต้อง

เอกสาร PDF หน้าแสดงผล 13 ใช้ตัวอย่าง ENTER_REV_WAIT ที่เริ่มนับแล้วคืนทันที ขณะที่เฟิร์มแวร์ต้นทางใช้ลูปหน่วง จึงเป็นคนละโครงสร้างการทำงาน แม้ตั้งใจให้พฤติกรรมเหมือนกัน ส่วนผล 21 จาก 21 ใน PDF เป็นของแบบจำลอง Python ไม่ใช่หลักฐานการรันเฟิร์มแวร์ฉบับนี้

## PASS 1: ฮาร์ดแวร์และขอบเขตการแยกไฟ

ผ่านการเทียบเอกสารกับสัญญาณที่กำหนด: P1.0–P1.2 อยู่ขา 1–3, P1.4–P1.6 อยู่ขา 5–7, P2.0–P2.7 อยู่ขา 21–28 และ P0.0–P0.2 อยู่ขา 39–37 ค่าไบต์ทั้ง 8 แถวคำนวณกลับเป็นบิตตรงตามข้อกำหนด

L293D ใช้ขา 1 เป็น EN1, ขา 2/7 เป็นอินพุต, ขา 3/6 เป็นเอาต์พุต, ขา 16 เป็นไฟลอจิก และขา 8 เป็นไฟมอเตอร์ ขา 4, 5, 12, 13 เป็นกราวด์ ฝั่งลอจิกกับมอเตอร์ใช้กราวด์ร่วมกัน ส่วน 12 V_S ของเซนเซอร์กับ 0 V_L ต้องแยกทางไฟฟ้าหากต้องการคงการแยกผ่านออปโต

วงจร NPN Light-ON → VO617A → HCT14 ให้ BEAM_DET=1 เมื่อแสงผ่าน และ 0 เมื่อแสงขาด การต่อ 100 nF เป็น bypass ที่รางไฟไอซี ไม่ใช่การใส่ตัวเก็บประจุเพื่อหน่วงลำแสง

อ้างอิงขาและพฤติกรรมอุปกรณ์: [AT89S52](https://ww1.microchip.com/downloads/en/DeviceDoc/doc1919.pdf), [L293D](https://www.ti.com/lit/ds/symlink/l293d.pdf), [SN74HCT14](https://www.ti.com/lit/ds/symlink/sn74hct14.pdf), [VO617A](https://www.vishay.com/docs/83430/vo617a.pdf)

## PASS 2: FSM

ชุดคำตอบมี 7 สถานะทำงานและ FAULT รวม 8 สถานะ ระบุเงื่อนไขเริ่มเครื่องครบทั้งปิดสุด เปิดสุด ไม่มีลิมิต และลิมิตขัดแย้ง ไม่มี auto-close และไม่มีเซนเซอร์คู่รุ่นเก่า

โค้ดอ้างอิงรอปล่อยปุ่มปิดคงที่ 20 ms แล้วรอกดใหม่คงที่ 20 ms ปฏิเสธคำสั่งที่ไม่ผ่าน guard และบังคับให้ปล่อยใหม่ รวมถึงตรวจ E-stop และลิมิตขัดแย้งในลูปรอทุกช่วง

ในฉบับอ้างอิง การรีเซ็ต FAULT ใช้การปล่อยแล้วกด PB_CLOSE ใหม่ ต่างจากต้นทางที่ยอมรับปุ่ม LOW ค้าง การกลับ INIT ตรวจตำแหน่งใหม่และไม่เริ่มมอเตอร์เอง

## PASS 3: Assembly และผลรันจริงในตัวจำลอง

- เฟิร์มแวร์ต้นทาง: ประกอบผ่าน EdSim51 2.1.39 แต่ยังมีข้อบกพร่องเชิงลอจิกข้างต้น
- โค้ดอ้างอิงเตรียมสอบ: ประกอบผ่านและทดสอบด้วย assembler กับ Cpu ของ EdSim51 2.1.39 โดยป้อนสัญญาณที่ P2 ผ่าน hardware pin API
- ผล: **42 กรณีผ่าน 0 กรณีล้มเหลว** ตรวจ 17,599,398 คำสั่ง
- ตรวจทุกคำสั่งว่า P2 latch คง FFH และเมื่อเปลี่ยนบิตทิศทาง RUN_N ต้องเป็น 1 ทั้งก่อนและหลังการเขียน
- ค่าที่วัดในกรณีทดสอบหนึ่ง: BEAM_DET เปลี่ยนเป็น 0 ถึง RUN_N เป็น 1 ใช้ 25 µs ในแบบจำลอง CPU ตัวเลขนี้ไม่ใช่ worst-case และไม่รวมความหน่วงเซนเซอร์ ออปโต อินเวอร์เตอร์ หรือ L293D จริง
- Coast ในกรณีทดสอบนับได้ 200,502 µs ซึ่งรวมเวลา settle 100 µs ของตัวทดสอบด้วย ใช้ยืนยันว่าไม่เริ่มขับก่อน 200 ms ไม่ใช่ผลวัดการหยุดเพลา
- Timeout ทดสอบว่ายังคงวิ่งเมื่อ 4,990 ms และเข้า FAULT ภายในอีก 30 ms จึงยืนยันระดับ nominal 5 s ไม่ใช่เส้นตาย 5.000000 s
- รูทีน ENTER ใช้ SETB P1.2 ก่อน ตั้งทิศโดยบังคับบิต RUN_N เป็น 1 แล้วเขียนค่า P1 เป้าหมาย การเปลี่ยน DDH → D9H หรือ EEH → EAH จึงเปลี่ยนเฉพาะบิต Enable
- เมื่อ CHECK พบ global trip จะออกไป FAULT โดยไม่กลับจาก call เดิม FAULT ตัดขับก่อนและตั้ง SP ใหม่ เพื่อไม่ให้คำสั่งหลัง call เดิมทำงานต่อหรือทิ้ง return address สะสม

แนวทางการใช้ assembler ตรวจเทียบกับ [คู่มือ EdSim51](https://edsim51.com/users-guide-2/) ผลทดสอบทั้งหมดเป็นของโค้ดอ้างอิงชุดนี้ ไม่ใช่การนำผล 21 กรณีจากแบบจำลองเดิมมาใช้แทน

**ข้อจำกัดที่ยังต้องเปิดเผย:** วิธี 250 รอบของ Timer 0 มี overhead หากต้องบังคับเส้นตาย 5.0 s อย่างเคร่งครัด ต้องเปลี่ยนฐานเวลาเป็นการติดตามเวลารวมและวัด worst-case เพิ่มเติม ชุดนี้คงวิธีนับรอบตามข้อกำหนดเพื่อใช้ในคำตอบระดับวิชา จึงไม่ประกาศว่าผ่านข้อกำหนด hard real-time ทุกประการ
