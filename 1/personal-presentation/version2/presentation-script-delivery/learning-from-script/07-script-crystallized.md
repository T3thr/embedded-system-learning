## หน้า 1 — ชื่อเรื่องและขอบเขต (0:00–0:15)

สวัสดีครับ ผม ธีรภัทร ภู่ระย้า รหัสนิสิต 66362416 วันนี้จะมานำเสนอหัวข้อ **Interrupt Mechanism** หรือกลไกการขัดจังหวะในระบบฝังตัวครับ

ประเด็นหลักที่จะนำเสนอประกอบด้วยสองส่วน คือความหมายและคุณสมบัติสำคัญของ interrupt รวมถึงลำดับขั้นตอนทางสถาปัตยกรรม ตั้งแต่การเกิดคำขอ จนกระทั่งตัวประมวลผลสามารถกลับมาประมวลผลโปรแกรมเดิมได้อย่างถูกต้องครับ

---

## หน้า 2 — นิยามและ 4 คุณสมบัติหลัก (0:15–0:55)

ประเด็นแรก ในการประมวลผลปกติ CPU จะรันคำสั่งไปตามลำดับ Interrupt คือกลไกที่อนุญาตให้ฮาร์ดแวร์ภายนอกหยุดการทำงานหลักของ CPU ชั่วคราว เพื่อถ่ายโอนการควบคุมไปยังฟังก์ชันบริการที่เรียกว่า **Interrupt Service Routine หรือ ISR** ก่อนจะกลับมาประมวลผลต่อจากจุดเดิม ต่างจากวิธี **Polling** ที่ CPU ต้องเสียรอบเวลาคอยวนตรวจอุปกรณ์ตลอดเวลา ซึ่งเปลืองพลังงานและตอบสนองช้ากว่าครับ

สไลด์ได้สรุป 4 คุณสมบัติสำคัญของ interrupt ไว้ดังนี้ครับ 

ประการแรก **Event-driven** หมายถึงการเปลี่ยนทิศทางโปรแกรมเกิดขึ้นจากเหตุการณ์หรือคำขอของฮาร์ดแวร์ ไม่ใช่การเรียกฟังก์ชันตามลำดับปกติ 

ประการที่สอง **State-preserving** หมายถึงการบันทึกบริบทเดิมของโปรแกรมไว้ก่อนเสมอ เพื่อให้สามารถกลับมาทำงานต่อได้อย่างถูกต้อง 

ประการที่สาม **Vectored** หมายถึงการมีตาราง Vector Table ระบุตำแหน่งที่อยู่ของ ISR ของแต่ละอุปกรณ์อย่างชัดเจน 

และประการสุดท้าย **Priority-aware** หมายถึงการมีลำดับความสำคัญคัดกรอง เมื่อมีคำขอเกิดขึ้นพร้อมกันครับ

---

## หน้า 3 — สามระยะการทำงาน (0:55–1:40)

สำหรับลำดับการทำงานทางสถาปัตยกรรม สไลด์แบ่งออกเป็น 3 ระยะครับ

ระยะแรก **Request** เมื่ออุปกรณ์เกิด event วงจรฮาร์ดแวร์จะตั้งค่า flag และส่งคำขอเข้าสู่สถานะ pending เพื่อรอการรับบริการ 

ระยะที่สอง **Entry** CPU จะตรวจสอบเงื่อนไข enable, mask และ priority เมื่อผ่านการอนุมัติ ระบบจะ preserve context ค้างไว้ แล้วเปิดดู Vector Table เพื่อกระโดดไปยังตำแหน่งเริ่มต้นของ ISR 

ระยะที่สาม **Service & Return** ISR จะจัดการสาเหตุของคำขอ เคลียร์ flag ที่ค้างไว้ แล้วคืนการทำงานกลับสู่โปรแกรมหลักครับ

หากยกตัวอย่างจาก 8051 ที่เราเรียนในวิชานี้ ในระยะ Entry CPU จะใช้ Stack Pointer ดันตำแหน่ง Program Counter เก็บลง Stack และเมื่อจบ ISR จะต้องใช้คำสั่ง **RETI** ไม่ใช่ RET ธรรมดา เพราะ RETI จะทำการคืนค่า PC พร้อมกับเปิดระบบ Global Interrupt กลับมาอีกครั้งตามที่ Lecture 4 อธิบายไว้ครับ

---

## หน้า 4 — เงื่อนไขที่ทำให้ทำงานถูกต้อง (1:40–2:15)

การทำให้กลไก interrupt ทำงานได้อย่างถูกต้องและเสถียร สไลด์ได้สรุปเงื่อนไขสำคัญไว้ 3 ประการครับ

ประการแรก **Qualify** คำขอต้องผ่านการตรวจสอบสิทธิ์และกรองสัญญาณก่อนเปลี่ยน control flow ทั้งการอนุมัติสิทธิ์ในระดับสวิตช์หลัก การเปิดปิดสิทธิ์รายอุปกรณ์ และระดับความสำคัญ เพื่อให้มั่นใจว่าคำขอที่เข้ามาได้รับการตอบสนองอย่างเหมาะสม

ประการที่สอง **Preserve** ต้องรักษาความถูกต้องของ context โดยการจัดเก็บและคืนค่า register อย่างสมดุล ป้องกันไม่ให้การทำงานของ ISR ไปส่งผลกระทบหรือสร้างความเสียหายต่อโปรแกรมหลัก

ประการที่สาม **Complete** ISR ต้องจัดการสาเหตุของคำขอ เคลียร์เงื่อนไขที่ค้างอยู่ คืนการทำงานด้วยกลไก return ที่ถูกต้อง และต้องออกแบบให้ทำงานกระชับที่สุดเท่าที่จำเป็น เพื่อลด latency และไม่กระทบต่อการตอบสนองของ interrupt ตัวอื่นในระบบครับ

---

## หน้า 5 — สรุปและอ้างอิง (2:15–2:30)

สรุปคือ Interrupt ไม่ใช่เพียงการกระโดดไปทำฟังก์ชันหนึ่งเฉยๆ แต่เป็นกลไกทางสถาปัตยกรรมฮาร์ดแวร์ที่ต้องคัดกรองคำขอ รักษาสถานะ และคืนการทำงานเดิมได้อย่างสมบูรณ์ภายใต้ข้อจำกัดด้านเวลาครับ

ข้อมูลทั้งหมดอ้างอิงจาก Mazidi, Microchip Datasheet ของ AVR และเสริมตัวอย่าง 8051 จาก Lecture 3 และ 4 ของวิชานี้ครับ ขอบคุณครับ
