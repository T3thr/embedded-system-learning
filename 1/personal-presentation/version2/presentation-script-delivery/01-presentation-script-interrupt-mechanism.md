## ก่อนเริ่มพูด

สไลด์ชุดนี้ใช้ภาพรวมของ interrupt mechanism ไม่ได้สอน register ของชิปเพียงรุ่นเดียว ดังนั้นคำว่า **vector, priority, context, return** ในช่วงต้นให้พูดในความหมายเชิงหลักการร่วม ส่วนเมื่อกล่าวถึง `EA`, `IE`, `IP`, vector address หรือ `RETI` ต้องระบุสถาปัตยกรรมเสมอ หากอาจารย์ถามว่าข้อมูลมาจาก 8051 หรือไม่ ให้ตอบว่า lecture 1–4 ใช้ 8051/MCS-51 เป็นแกน ส่วนสไลด์ใช้ AVR และ ARM เป็นเอกสารเสริมเพื่ออธิบายแนวคิดร่วม ไม่ควรย้ายเลข address หรือพฤติกรรมของสถาปัตยกรรมหนึ่งไปใช้กับอีกสถาปัตยกรรมหนึ่ง [1] [2] [3]

## สไลด์ที่ 2: ความหมายและคุณลักษณะของ interrupt

**เวลา 0:15–0:48**

### บทพูด

Interrupt คือกลไกที่ทำให้ตัวประมวลผล **ถ่ายโอนการควบคุมชั่วคราว** จากโปรแกรมที่กำลังทำงานไปยัง **Interrupt Service Routine หรือ ISR** เมื่อมีคำขอที่ผ่านเงื่อนไขของระบบ คำขอนี้อาจมาจากเหตุการณ์ของ peripheral หรือสัญญาณภายนอก และไม่ได้เกิดขึ้นตามจังหวะเดียวกับลำดับคำสั่งของโปรแกรมเสมอไป

จากสไลด์ มีคุณลักษณะสำคัญสี่ประการ ประการแรกคือ **event-driven** หมายความว่า control flow เปลี่ยนเพราะมีเหตุการณ์หรือคำขอ ไม่ใช่เพราะโปรแกรมหลักเรียกฟังก์ชันตามลำดับปกติ ประการที่สองคือ **state-preserving** หมายความว่าเมื่อ ISR จบ โปรแกรมเดิมต้องกลับมาทำต่อในบริบทที่ถูกต้อง ประการที่สามคือ **vectored** หมายความว่าระบบมีตำแหน่งหรือกลไกที่ใช้ระบุว่าจะเริ่ม handler ของแหล่งใด ประการที่สี่คือ **priority-aware** หมายความว่าการตอบรับอาจขึ้นกับ enable, mask และ priority ของคำขอ

ในเชิงเปรียบเทียบ interrupt ช่วยให้ CPU ไม่จำเป็นต้องวนตรวจอุปกรณ์ทุกครั้งแบบ polling แต่ประเด็นหลักของวันนี้ไม่ใช่การกล่าวว่า interrupt ดีกว่า polling ในทุกกรณี เพราะ polling อาจเหมาะกับงานที่เรียบง่ายหรือคาดการณ์ได้ สิ่งที่ interrupt เพิ่มขึ้นคือกลไกตอบสนองต่อเหตุการณ์และการจัดการเวลา โดยต้องแลกกับความซับซ้อนของการรักษา context และการควบคุมลำดับความสำคัญ [5]

### จุดที่ต้องเข้าใจก่อนพูด

คำว่า **control flow** คือเส้นทางการทำงานของคำสั่งในโปรแกรม คำว่า **handler** คือโค้ดที่รับผิดชอบเหตุการณ์ ส่วน **ISR** คือ handler ที่ถูกเรียกเพื่อบริการ interrupt คำว่า **context** คือข้อมูลสถานะที่จำเป็นต่อการทำงานต่อ เช่น program counter, register และ status state โดยรายการที่ hardware เก็บให้อัตโนมัติแตกต่างกันตามสถาปัตยกรรม

### แหล่งอ้างอิงสำหรับสไลด์นี้

Mazidi อธิบายความแตกต่างระหว่าง interrupt กับ polling, ความหมายของ ISR และ vector table ในหนังสือบท interrupt หน้า 375–376 และอธิบายลำดับการตอบสนองในหน้า 376 [5] สำหรับระบบฝังตัวทั่วไป Lecture 1 หน้า 3–4 บรรทัด 35–74 อธิบายความสัมพันธ์ระหว่าง hardware, software, input, output และการทำงานภายใต้เวลา [4]

## สไลด์ที่ 3: สามระยะของกลไก interrupt

**เวลา 0:48–1:34**

### บทพูด

กลไกในสไลด์แบ่งเป็นสามระยะ ระยะแรกคือ **Request** เมื่ออุปกรณ์หรือ peripheral เกิด event วงจรจะสร้าง request หรือเปลี่ยนสถานะ flag และคำขออาจอยู่ในสถานะ pending หมายถึงเกิดขึ้นแล้วแต่ยังไม่ได้รับบริการ ระยะที่สองคือ **Entry** วงจรควบคุมตรวจว่า request นั้นเปิดใช้งานหรือไม่ ถูก mask หรือไม่ และมี priority เพียงพอหรือไม่ ถ้าผ่านเงื่อนไข ระบบจะ preserve context ตามที่สถาปัตยกรรมกำหนดและใช้ vector เพื่อหาจุดเริ่มต้นของ handler

ระยะที่สามคือ **Service and Return** ISR จะจัดการสาเหตุของคำขอ เช่น อ่านข้อมูลหรือเคลียร์เงื่อนไขที่ทำให้เกิด interrupt จากนั้นใช้กลไก return เพื่อคืน program counter และสถานะที่จำเป็น แล้ว resume โปรแกรมเดิม ลำดับนี้เป็นแบบจำลองร่วมของหลายสถาปัตยกรรม แต่รายละเอียดต้องแยกกัน ตัวอย่างเช่น AVR อธิบายการจบคำสั่งปัจจุบัน เก็บ program counter ใช้ vector table และจบ ISR ด้วย `RETI` [5] ขณะที่ Cortex-M3 มีการ stacking ของ stack frame และ vector fetch โดย hardware และมีแนวคิด exception return ที่ใช้ `EXC_RETURN` [6] ส่วน classic 8051 ใช้ fixed vector address และ hardware-generated LCALL โดย manual ระบุว่าฮาร์ดแวร์เก็บ PC แต่ไม่เก็บ PSW ให้ ISR โดยอัตโนมัติ ดังนั้น ISR ต้องรักษา register หรือสถานะอื่นที่ตนเองแก้ไข [7]

### จุดที่ต้องเข้าใจก่อนพูด

**Flag** คือบิตหรือสถานะที่บอกว่าเงื่อนไขหนึ่งเกิดขึ้นแล้ว **pending** คือคำขอที่รอการรับบริการ **vector** คือข้อมูลหรือตำแหน่งที่ใช้ระบุ handler **stack** คือหน่วยความจำแบบ LIFO ที่ใช้เก็บข้อมูลชั่วคราวและ return address และ **program counter หรือ PC** คือ register ที่ชี้คำสั่งถัดไปของโปรแกรม

ใน 8051 lecture 3 อธิบายว่า stack ใช้เก็บ return address ของ ISR และ subroutine โดย SP ชี้ตำแหน่งบน stack; Lecture 3 หน้า 9 บรรทัด 496–512 [8] ส่วน SFR ที่ใช้ควบคุม interrupt ได้แก่ `IE` ที่ address `A8H` และ `IP` ที่ `B8H` ตามตาราง Lecture 3 หน้า 12 บรรทัด 667–746 [8] ทั้งนี้ vector address และจำนวน priority ต้องอ้างอิงชิป 8051 รุ่นที่กำลังพูดถึง เพราะ derivative อาจมีแหล่ง interrupt เพิ่มขึ้น [7]

## สไลด์ที่ 4: เงื่อนไขความถูกต้องของการตอบสนอง

**เวลา 1:34–2:12**

### บทพูด

การทำให้ interrupt ทำงานถูกต้องต้องพิจารณาสามเงื่อนไข คือ **qualify, preserve และ complete**

หนึ่ง **qualify** คำขอต้องผ่านกฎ enable, mask และ priority ก่อนจึงจะเปลี่ยน control flow ได้ ใน 8051 `EA` เป็น global enable และ `IE` ใช้เปิดหรือปิดแหล่ง interrupt รายตัว ส่วน `IP` ใช้กำหนด priority ตามรุ่นที่รองรับ [7] ใน AVR มี global interrupt bit และ enable bit รายแหล่ง ซึ่งเป็นชื่อ register คนละชุด จึงไม่ควรนำ `EA`, `IE` หรือ `IP` ไปเรียกแทน AVR

สอง **preserve** ต้องรักษา context integrity หรือความถูกต้องของบริบทเดิม เมื่อ ISR แก้ register หรือ status ที่โปรแกรมเดิมยังต้องใช้ จะต้อง save และ restore อย่างสมดุล ใน classic 8051 manual ระบุว่า interrupt response เก็บ PC แต่ไม่เก็บ PSW โดยอัตโนมัติ ดังนั้น ISR ต้องรับผิดชอบสถานะเพิ่มเติมเอง [7] จุดนี้เชื่อมกับ Lecture 3 หน้า 9 ที่อธิบาย stack และการเก็บ return address [8]

สาม **complete** ISR ต้องจัดการสาเหตุของคำขอและคืนระบบด้วยคำสั่งหรือกลไก return ที่ถูกต้อง สำหรับ 8051 ต้องแยก `RET` ซึ่งใช้คืนจาก subroutine ปกติ ออกจาก `RETI` ซึ่งใช้จบ ISR และแจ้ง interrupt-control logic ว่าการบริการสิ้นสุดแล้ว Lecture 4 หน้า 28 บรรทัด 1391–1416 อธิบายความแตกต่างนี้ [9] แต่ถ้าพูดเชิงสถาปัตยกรรมอย่างเคร่งครัด ไม่ควรสรุปว่า `RETI` เป็นคำสั่งที่เขียน `EA = 1` ในทุก 8051 derivative; Intel MCS-51 manual อธิบายว่า `RETI` คืน PC และทำให้ interrupt logic ยอมรับ interrupt ระดับเดียวกันได้อีก ส่วนการเปลี่ยนค่า `EA` ต้องตรวจสอบคู่มือของอุปกรณ์ [7]

สุดท้าย ISR ควรทำงานสั้นและมีขอบเขตเวลา เพราะ ISR ที่นานหรือการปิด interrupt เป็นเวลานานเพิ่ม latency และ jitter ของเหตุการณ์อื่น คำว่า bounded ISR ในที่นี้หมายถึงเราสามารถอธิบายหรือประมาณขอบเขตเวลาการทำงานได้ ไม่ได้หมายความว่าทุก ISR ต้องมีเวลาเท่ากัน

### จุดที่ต้องเข้าใจก่อนพูด

**Enable** คือการอนุญาตให้แหล่ง interrupt ตอบสนอง **mask** คือเงื่อนไขที่ป้องกันหรือกรองคำขอ **priority** คือกฎตัดสินว่าเมื่อมีหลายคำขอ คำขอใดมีสิทธิ์ก่อน **latency** คือเวลาตั้งแต่เหตุการณ์เกิดจน handler เริ่มทำงาน และ **jitter** คือความแปรผันของเวลาตอบสนองระหว่างเหตุการณ์ที่ควรมีพฤติกรรมใกล้เคียงกัน

## สไลด์ที่ 5: สรุปและเอกสารอ้างอิง

**เวลา 2:12–2:25**

### บทพูด

สรุปคือ interrupt ไม่ใช่เพียงการกระโดดไปยังฟังก์ชัน แต่เป็นลำดับทางสถาปัตยกรรมที่ต้องคัดกรองคำขอ รักษาสถานะ จัดการสาเหตุของคำขอ และคืนการทำงานเดิมอย่างถูกต้องภายใต้ข้อจำกัดด้านเวลา ในการอ่านเอกสารต้องแยกหลักการร่วมออกจากรายละเอียดเฉพาะของ 8051, AVR และ Cortex-M3 โดยผมใช้ lecture 1–4 เป็นบริบทของรายวิชา ใช้ Mazidi และ Microchip เป็นแหล่งอธิบาย AVR ใช้ Arm เป็นแหล่งเปรียบเทียบ Cortex-M3 และใช้ Intel MCS-51 manual ตรวจสอบ semantics ของ 8051 ขอบคุณครับ
