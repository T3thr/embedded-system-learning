### ข้อ 1: ความหมายและองค์ประกอบของ Embedded System

#### 🔴 โจทย์ที่จำออกมา (Red Text):
> **1. Embedded System คืออะไร มีองค์ประกอบอะไรบ้าง**

#### 🔵 บันทึกแนวทางของรุ่นพี่ (Blue Text):
> - Microcontroller หรือระบบที่ใช้ microprocessor ที่ออกแบบมาทำงานเฉพาะอย่าง  
> - มี 3 องค์ประกอบ คือ 1. Hardware 2. Application Software 3. Real Time Operating System (RTOS)

#### 🔍 วิเคราะห์สิ่งที่อาจารย์ต้องการวัดผล:
อาจารย์ต้องการดูว่านักศึกษาเข้าใจ **นิยามเชิงวิศวกรรม** ของระบบสมองกลฝังตัวว่าต่างจากคอมพิวเตอร์ทั่วไปอย่างไร และสามารถระบุ **องค์ประกอบหลัก 3 ส่วน (Building Blocks)** พร้อมยกตัวอย่างหน้าที่ของแต่ละส่วนได้ถูกต้องครบถ้วนหรือไม่

#### 🟢 คำตอบฉบับสมบูรณ์สำหรับใช้ในห้องสอบ (Official Answer):
1. **นิยามของ Embedded System (ระบบสมองกลฝังตัว):**
   - คือระบบคอมพิวเตอร์ (ที่ใช้ Microcontroller หรือ Microprocessor) ซึ่งถูกสร้างหรือ **ฝังตัวอยู่ภายในอุปกรณ์/ผลิตภัณฑ์ขนาดใหญ่** เพื่อทำหน้าที่ควบคุม ประมวลผล หรือทำงาน **เฉพาะทางอย่างใดอย่างหนึ่งโดยเฉพาะ (Dedicated / Specific Function)** 
   - มักทำงานแบบเวลาจริง (**Real-Time System**) ที่ต้องมีความถูกต้องทั้งเชิงตรรกะและทันเวลา (Deadline) ภายใต้ข้อจำกัดด้านทรัพยากร (จำกัดขนาด, พลังงาน, หน่วยความจำ และต้นทุน)
   - *ตัวอย่าง:* ระบบควบคุมในเครื่องซักผ้า, ระบบเบรก ABS ในรถยนต์, ไมโครเวฟ, เราเตอร์, เครื่องวัดอุณหภูมิดิจิทัล

2. **องค์ประกอบหลัก 3 ส่วน (3 Core Components):**
   - **1. ฮาร์ดแวร์ (Hardware):** ชิปประมวลผล (MCU เช่น 8051/ARM), หน่วยความจำ (ROM/Flash สำหรับ Code, RAM สำหรับ Data), พอร์ต I/O, Timers/Counters, วงจร Interrupts, วงจรเชื่อมต่อสัญญาณ (Interface Circuits), เซนเซอร์ (Sensors) และตัวขับกำลัง (Actuators)
   - **2. ซอฟต์แวร์ประยุกต์ (Application Software / Firmware):** ชุดคำสั่งที่โปรแกรมเมอร์เขียนขึ้นมาเฉพาะสำหรับงานนั้นๆ (เขียนด้วย Assembly หรือ C) เพื่อควบคุมลอจิกการทำงานและโต้ตอบกับอุปกรณ์ภายนอก
   - **3. ระบบปฏิบัติการเวลาจริง (Real-Time Operating System - RTOS) / System Control:** ซอฟต์แวร์ระบบที่ทำหน้าที่จัดการ Task Scheduling, Resource Allocation, และควบคุม Timing ให้ตอบสนองต่อเหตุการณ์ได้ทันเวลาอย่างแม่นยำ *(หมายเหตุ: ในระบบขนาดเล็ก เช่น 8051 ทั่วไป อาจใช้โครงสร้างแบบ Bare-metal / Super-loop ควบคุมแทนได้)*

#### ⚠️ ข้อควรระวังและการประเมินแนวทางรุ่นพี่:
- รุ่นพี่ตอบถูกประเด็นหลัก แต่สั้นมาก หากอาจารย์ต้องการคำอธิบายย่อย 3 องค์ประกอบ ถ้าเขียนแค่ชื่อ 1-2-3 อาจได้คะแนนไม่เต็ม ควรอธิบายหน้าที่สั้นๆ ของ Hardware, Software, และ RTOS ประกอบด้วย

### ข้อ 2: เปรียบเทียบ Microprocessor กับ Microcontroller

#### 🔴 โจทย์ที่จำออกมา (Red Text):
> **2. Microprocessor และ Microcontroller แตกต่างกันอย่างไร**

#### 🔵 บันทึกแนวทางของรุ่นพี่ (Blue Text):
> - Microprocessor มีความยืดหยุ่นมากกว่า ใช้สำหรับวัตถุประสงค์ทั่วไป  
> - Microcontroller มีความยืดหยุ่นน้อยกว่า ออกแบบมาเพื่อทำงานเฉพาะอย่าง จำเป็นต้องมีการทำงานเฉพาะอย่าง

#### 🔍 วิเคราะห์สิ่งที่อาจารย์ต้องการวัดผล:
ข้อนี้เป็นข้อสอบยอดฮิตตลอดกาล (มักมีคะแนน 5 - 10 คะแนน) อาจารย์ต้องการดูการเปรียบเทียบในเชิง **สถาปัตยกรรมฮาร์ดแวร์ (Hardware Architecture)**, **การต่อประสานบัส (Bus Interface)**, **การใช้พลังงาน**, **ต้นทุน**, และ **ลักษณะการใช้งานจริง** ไม่ใช่แค่ตอบเรื่องความยืดหยุ่นเพียงประโยคเดียว

#### 🟢 คำตอบฉบับสมบูรณ์สำหรับใช้ในห้องสอบ (Official Answer):
ควรตอบในรูปแบบ **ตารางเปรียบเทียบ 6 มิติ** ดังนี้:

| มิติการเปรียบเทียบ | ไมโครโปรเซสเซอร์ (Microprocessor - MPU) | ไมโครคอนโทรลเลอร์ (Microcontroller - MCU) |
| :--- | :--- | :--- |
| **1. โครงสร้างภายในชิป (Architecture)** | มีเฉพาะหน่วยประมวลผลกลาง (**CPU Only**: ALU, Control Unit, General Registers) บนชิป ไม่มี RAM, ROM, I/O ในตัว | เป็นคอมพิวเตอร์ชิปเดี่ยว (**Single-Chip Computer**: รวม CPU, RAM, ROM/Flash, I/O Ports, Timers, Interrupts, Serial บนชิปเดียว) |
| **2. การต่อใช้งาน (System Connection)** | ต้องต่อชิปภายนอกเพิ่ม (External RAM, ROM, I/O Controller) ผ่าน System Bus ภายนอก | ไม่จำเป็นต้องต่อชิปภายนอกเพิ่ม มีวงจรและพอร์ตเชื่อมต่อกับเซนเซอร์/อุปกรณ์ได้โดยตรง |
| **3. วัตถุประสงค์ (Application)** | **งานประมวลผลทั่วไป (General Purpose)** เช่น คอมพิวเตอร์ PC, แล็ปท็อป, เซิร์ฟเวอร์ ที่ต้องรันโปรแกรมหลากหลาย | **งานควบคุมเฉพาะทาง (Dedicated / Embedded Control)** เช่น เครื่องซักผ้า, แอร์, รีโมทคอนโทรล, ECU รถยนต์ |
| **4. ความยืดหยุ่นและการอัปเกรด** | **ยืดหยุ่นสูงมาก** สามารถเพิ่มความจุ RAM, พื้นที่ Harddisk, เปลี่ยนการ์ดจอได้ตามต้องการ | **สเปกคงที่** ขนาด RAM, ROM และขา I/O ถูกกำหนดตายตัวตามเบอร์ชิปจากโรงงาน |
| **5. การใช้พลังงานและขนาด** | ใช้กำลังไฟฟ้าสูง (หลายวัตต์ถึงร้อยวัตต์) มีความร้อนสูง ขนาดบอร์ดวงจรใหญ่ | กินพลังงานต่ำมาก (หลักมิลลิวัตต์/ไมโครแอมป์) ทำงานด้วยแบตเตอรี่ได้ ขนาดกะทัดรัด |
| **6. ต้นทุนระบบโดยรวม (System Cost)** | ต้นทุนรวมสูง เนื่องจากต้องใช้อุปกรณ์และชิปเสริมภายนอกจำนวนมาก | ต้นทุนรวมต่อหน่วยต่ำมาก เหมาะสำหรับการผลิตเชิงอุตสาหกรรมจำนวนมาก |

#### ⚠️ ข้อควรระวังและการประเมินแนวทางรุ่นพี่:
- การตอบเพียง "MPU ยืดหยุ่นกว่า ใช้ทั่วไป / MCU ยืดหยุ่นน้อยกว่า ทำเฉพาะอย่าง" จะได้คะแนนเพียง 2-3 คะแนนจาก 10 คะแนนเต็ม **ต้องระบุเรื่องโครงสร้าง CPU-only vs All-in-One ในชิปเดียวเสมอ!**

### ข้อ 3: เปรียบเทียบสถาปัตยกรรม Von Neumann กับ Harvard

#### 🔴 โจทย์ที่จำออกมา (Red Text):
> **3. Von Neumann และ Harvard แตกต่างกันอย่างไร**

#### 🔵 บันทึกแนวทางของรุ่นพี่ (Blue Text):
> - Von Neumann : data และ code อยู่ในหน่วยความจำเดียวกัน, มีการออกแบบเรียบง่าย, pipelining not possible, 2 set of clocks cycles ( 1 รอบ สำหรับ การดึงข้อมูล, 1 รอบ สำหรับ การดึงคำสั่ง)  
> - Harvard : data และ code อยู่ในหน่วยความจำที่แตกต่างกัน, มีความซับซ้อนในการออกแบบ, pipelining is possible, single clock cycle (สำหรับการดึงข้อมูล และการดึงคำสั่ง)

#### 🔍 วิเคราะห์สิ่งที่อาจารย์ต้องการวัดผล:
อาจารย์ต้องการทดสอบความเข้าใจเรื่อง **โครงสร้างการจัดสรรหน่วยความจำและสายสัญญาณบัส (Memory Space & Bus Structure)** ซึ่งเป็นพื้นฐานที่อธิบายว่าทำไม 8051 ถึงแยกคำสั่งอ่าน Program ROM (`MOVC`) ออกจาก Data RAM (`MOVX`)

#### 🟢 คำตอบฉบับสมบูรณ์สำหรับใช้ในห้องสอบ (Official Answer):

```
[ Von Neumann Architecture ]             [ Harvard Architecture ]
+---------------------------+             +-------------+  +-------------+
|    Program Code & Data    |             | Program ROM |  |  Data RAM   |
|   (Shared Memory Space)   |             | (Code Space)|  | (Data Space)|
+-------------+-------------+             +------+------+  +------+------+
              | Address & Data Bus (แชร์กัน)      | Code Bus       | Data Bus (แยกกัน)
       +------+------+                           +-------+--------+
       |     CPU     |                           |      CPU       |
       +-------------+                           +----------------+
```

1. **สถาปัตยกรรมแบบ Von Neumann (Princeton Architecture):**
   - **โครงสร้าง:** ใช้หน่วยความจำทางกายภาพร่วมกัน (Unified Memory) เก็บทั้งรหัสโปรแกรมคำสั่ง (Code/Instruction) และข้อมูลตัวแปร (Data) อยู่ใน Address Space เดียวกัน
   - **ระบบบัส:** ใช้ Address Bus และ Data Bus ร่วมกันเพียงชุดเดียว
   - **การทำงานและข้อจำกัด:** CPU ไม่สามารถดึงคำสั่ง (Fetch) และอ่าน/เขียนข้อมูล (Data Access) พร้อมกันใน Clock เดียวกันได้ (เกิด **Von Neumann Bottleneck**) ทำให้ต้องใช้รอบสัญญาณนาฬิกาอย่างน้อย 2 รอบ (1 รอบดึงคำสั่ง, 1 รอบดึงข้อมูล) และทำ Pipelining ได้ยาก
   - **ข้อดี:** การออกแบบวงจรเรียบง่าย สายสัญญาณบนชิปน้อย ต้นทุนต่ำ

2. **สถาปัตยกรรมแบบ Harvard Architecture:**
   - **โครงสร้าง:** แยกหน่วยความจำสำหรับเก็บโปรแกรม (Instruction/Code Memory) และหน่วยความจำสำหรับเก็บข้อมูล (Data Memory) ออกจากกันอย่างเด็ดขาดทั้งทางตรรกะและกายภาพ
   - **ระบบบัส:** มีชุด Address Bus และ Data Bus แยกกันคนละชุด (Code Bus และ Data Bus)
   - **การทำงานและข้อดี:** CPU สามารถอ่าน/เขียนข้อมูลใน Data RAM ไปพร้อมๆ กับการดึงคำสั่งถัดไปจาก Program ROM ได้ในเวลาเดียวกัน (**Simultaneous Access**) รองรับระบบ **Pipelining** ทำงานเสร็จใน Single Machine Cycle ได้อย่างมีประสิทธิภาพ
   - **ข้อจำกัด:** วงจรมีความซับซ้อนมากกว่า ใช้จำนวนสายบัสภายในมากกว่า
   - **การนำไปใช้ในวิชานี้:** ไมโครคอนโทรลเลอร์ตระกูล **MCS-51 / 8051 ใช้โครงสร้าง Modified Harvard Architecture**

#### ⚠️ ข้อควรระวังและการประเมินแนวทางรุ่นพี่:
- โน้ตของรุ่นพี่ในข้อนี้ถือว่าสรุปหัวใจสำคัญมาได้ดีมาก สามารถนำประเด็น Code/Data Memory, Bus, Clock Cycles, และ Pipelining มาเขียนตอบได้เลย แต่ให้เพิ่มรูปไดอะแกรมแนวคิดเข้าไปด้วยเพื่อความสมบูรณ์

### ข้อ 4: ขนาดหน่วยความจำ Internal ROM และ Internal RAM ใน 8051

#### 🔴 โจทย์ที่จำออกมา (Red Text):
> **4. Internal ROM และ Internal RAM มีขนาดเท่าไหร่**

#### 🔵 บันทึกแนวทางของรุ่นพี่ (Blue Text):
> - Internal ROM มีขนาด 4 Kbyte  
> - Internal RAM มีขนาด 128 byte

#### 🔍 วิเคราะห์สิ่งที่อาจารย์ต้องการวัดผล:
อาจารย์ต้องการทดสอบตัวเลขสเปกมาตรฐานของ 8051 (Standard MCS-51) และหากต้องการได้คะแนนเต็ม **ต้องระบุช่วงแอดเดรส (Address Range) และการแบ่งโซนภายใน RAM (Register Bank, Bit RAM, General RAM)** ด้วย!

#### 🟢 คำตอบฉบับสมบูรณ์สำหรับใช้ในห้องสอบ (Official Answer):
1. **Internal Program ROM (หน่วยความจำโปรแกรมภายใน):**
   - **ขนาด:** **4 Kbytes** (ช่วงแอดเดรส **`0000H` ถึง `0FFFH`**)
   - ควบคุมการอ่านผ่านขา $\overline{\text{EA}}$ (External Access):
     - $\overline{\text{EA}} = 1$: เริ่มรันโปรแกรมจาก Internal ROM (`0000H - 0FFFH`) ก่อน เมื่อเกินจะข้ามไปอ่าน External ROM (`1000H - FFFFH`)
     - $\overline{\text{EA}} = 0$: รันโปรแกรมจาก External ROM ภายนอกทั้งหมด (`0000H - FFFFH` สูงสุด 64 KB)

2. **Internal Data RAM (หน่วยความจำข้อมูลภายใน):**
   - **ขนาด:** **128 Bytes** (ช่วงแอดเดรส **`00H` ถึง `7FH`**)
   - มีการจัดสรรโครงสร้างพื้นที่ภายในเป็น 3 ส่วนหลัก:
     - **`00H - 1FH` (32 Bytes):** **Register Banks 4 ชุด (Bank 0 – 3)** แต่ละ Bank มีรีจิสเตอร์ $R_0 - R_7$ รวม 8 ตัว
     - **`20H - 2FH` (16 Bytes):** **Bit-Addressable RAM** พื้นที่เข้าถึงระดับบิตได้ รวม 128 บิต (บิตแอดเดรส `00H - 7FH`)
     - **`30H - 7FH` (80 Bytes):** **General-Purpose Scratchpad RAM** สำหรับเก็บตัวแปรทั่วไปและใช้งานเป็น Stack
   *(หมายเหตุเสริม: ถ้าเป็นชิปเบอร์ 8052 จะมี Internal RAM ขนาด 256 Bytes โดยช่วง `80H - FFH` ด้านบนจะแชร์แอดเดรสกับ SFR แต่ต้องเข้าถึงผ่าน Indirect Addressing `@R0/@R1`)*

### ข้อ 5: จำนวนและลักษณะพอร์ต I/O ของ 8051

#### 🔴 โจทย์ที่จำออกมา (Red Text):
> **5. Microcontroller 8051 มีทั้งหมดกี่พอร์ต**

#### 🔵 บันทึกแนวทางของรุ่นพี่ (Blue Text):
> - 4 port (P0 – P3)

#### 🔍 วิเคราะห์สิ่งที่อาจารย์ต้องการวัดผล:
การถามว่ามีกี่พอร์ตไม่ได้ต้องการแค่ตัวเลข 4 พอร์ต แต่ต้องการทราบ:
1. แต่ละพอร์ตมีขนาดกี่บิต (8 บิต รวม 32 I/O pins)
2. โครงสร้างทางไฟฟ้า (Open-Drain vs Quasi-bidirectional with Pull-up)
3. **หน้าที่พิเศษรอง (Alternate Special Functions)** ของแต่ละพอร์ต!

#### 🟢 คำตอบฉบับสมบูรณ์สำหรับใช้ในห้องสอบ (Official Answer):
ไมโครคอนโทรลเลอร์ 8051 มีพอร์ตอินพุต/เอาต์พุตทั้งหมด **4 พอร์ต (Port 0 – Port 3) แต่ละพอร์ตมีขนาด 8 บิต รวมทั้งหมด 32 ขา I/O**:

1. **Port 0 (`P0.0 - P0.7`, SFR Address `80H`, ขา 39-32):**
   - เป็นพอร์ตแบบ **Open-Drain Bidirectional** (ไม่มี internal pull-up resistor) หากใช้เป็น General I/O จะต้องต่อตัวต้านทาน Pull-up ภายนอก
   - **หน้าที่พิเศษ (Dual Function):** ทำหน้าที่เป็น **Multiplexed Low-order Address / Data Bus (`AD0 - AD7`)** ในการเชื่อมต่อกับหน่วยความจำภายนอก (External Memory)
2. **Port 1 (`P1.0 - P1.7`, SFR Address `90H`, ขา 1-8):**
   - เป็นพอร์ตแบบ **Quasi-Bidirectional** มี Internal Pull-up ในตัว ทำหน้าที่เป็น General Purpose I/O อย่างสมบูรณ์
3. **Port 2 (`P2.0 - P2.7`, SFR Address `A0H`, ขา 21-28):**
   - เป็นพอร์ตแบบ **Quasi-Bidirectional** มี Internal Pull-up ในตัว
   - **หน้าที่พิเศษ:** ทำหน้าที่ส่ง **High-order Address Bus (`A8 - A15`)** เมื่อเชื่อมต่อกับ External Memory ขนาด 16 บิต
4. **Port 3 (`P3.0 - P3.7`, SFR Address `B0H`, ขา 10-17):**
   - เป็นพอร์ตแบบ **Quasi-Bidirectional** มี Internal Pull-up ในตัว
   - **หน้าที่พิเศษเฉพาะขา (Alternate Functions):**
     - `P3.0 (RxD)` / `P3.1 (TxD)` : รับ/ส่งข้อมูลอนุกรม (Serial Interface)
     - `P3.2 (INT0)` / `P3.3 (INT1)` : สัญญาณขัดจังหวะภายนอก (External Interrupts)
     - `P3.4 (T0)` / `P3.5 (T1)` : ขาอินพุตของตัวนับเวลา (Timer/Counter External Clock)
     - `P3.6 (WR)` / `P3.7 (RD)` : สัญญาณควบคุมการเขียน/อ่านหน่วยความจำภายนอก

### ข้อ 6: หน้าที่และลักษณะของ Register B

#### 🔴 โจทย์ที่จำออกมา (Red Text):
> **6. Register B คืออะไร**

#### 🔵 บันทึกแนวทางของรุ่นพี่ (Blue Text):
> - เป็น register 8 bit มีไว้สำหรับการคูณ และการหาร

#### 🔍 วิเคราะห์สิ่งที่อาจารย์ต้องการวัดผล:
อาจารย์ต้องการให้ระบุ:
1. Address และคุณสมบัติของ Register B (เป็น SFR Address `F0H`, Bit-addressable)
2. การทำงานในคำสั่ง **`MUL AB`** (ผลลัพธ์ 16 บิต: High byte ใน B, Low byte ใน A)
3. การทำงานในคำสั่ง **`DIV AB`** (ผลหารใน A, เศษเหลือใน B)
4. การใช้งานทั่วไปเป็น General Register เมื่อไม่ได้คำนวณคณิตศาสตร์

#### 🟢 คำตอบฉบับสมบูรณ์สำหรับใช้ในห้องสอบ (Official Answer):
- **Register B** เป็นรีจิสเตอร์ฟังก์ชันพิเศษ (**SFR ขนาด 8 บิต**) อยู่ที่ตำแหน่งแอดเดรส **`F0H`** (สามารถเข้าถึงระดับบิตได้ / Bit-addressable)
- **หน้าที่หลัก:** ใช้งานร่วมกับ Accumulator (A) ในการคำนวณทางคณิตศาสตร์เฉพาะคำสั่งคูณและหาร:
  1. **คำสั่งคูณ `MUL AB`:** นำค่าใน $A$ คูณกับค่าใน $B$ ผลลัพธ์ขนาด 16 บิตจะถูกเก็บแยกเป็น:
     - **High Byte (ไบต์บน)** $\rightarrow$ เก็บใน **Register B**
     - **Low Byte (ไบต์ล่าง)** $\rightarrow$ เก็บใน **Accumulator A**
     - (หากผลคูณ $> 255$ แฟลก $OV$ จะถูกเซ็ตเป็น `1`)
  2. **คำสั่งหาร `DIV AB`:** นำค่าใน $A$ หารด้วยค่าใน $B$ ($A \div B$):
     - **ผลหาร (Quotient)** $\rightarrow$ เก็บใน **Accumulator A**
     - **เศษเหลือ (Remainder)** $\rightarrow$ เก็บใน **Register B**
     - (หากตัวหาร $B = 0$ แฟลก $OV$ จะถูกเซ็ตเป็น `1` เตือน Division by Zero)
- **หน้าที่รอง:** เมื่อไม่ได้ใช้ในการคูณหาร สามารถใช้ Register B เป็นที่พักข้อมูลชั่วคราว (General-Purpose Register) ได้เหมือนรีจิสเตอร์ทั่วไป

### ข้อ 7: ชื่อเต็มและโครงสร้างบิตของ PSW

#### 🔴 โจทย์ที่จำออกมา (Red Text):
> **7. PSW มีชื่อเต็มว่าอะไร**

#### 🔵 บันทึกแนวทางของรุ่นพี่ (Blue Text):
> - Program Status Word (PSW)

#### 🔍 วิเคราะห์สิ่งที่อาจารย์ต้องการวัดผล:
แม้โจทย์ที่จำออกมาจะถามแค่ชื่อเต็ม แต่ในข้อสอบจริงอาจารย์มักจะมีข้อย่อยหรือตารางให้ระบุ **ความหมายของแต่ละบิตใน PSW (Flag Descriptions)** เพื่อดูว่าเข้าใจการเปลี่ยนสถานะของระบบหรือไม่

#### 🟢 คำตอบฉบับสมบูรณ์สำหรับใช้ในห้องสอบ (Official Answer):
- **ชื่อเต็ม:** **Program Status Word (PSW)**
- **ตำแหน่ง:** เป็นรีจิสเตอร์ SFR ขนาด 8 บิต อยู่ที่แอดเดรส **`D0H`** (Bit-addressable)
- **โครงสร้างบิตทั้ง 8 (Bit Map):**

```text
+-------+-------+-------+-------+-------+-------+-------+-------+
| Bit 7 | Bit 6 | Bit 5 | Bit 4 | Bit 3 | Bit 2 | Bit 1 | Bit 0 |
|  CY   |  AC   |  F0   |  RS1  |  RS0  |  OV   |  UD   |   P   |
+-------+-------+-------+-------+-------+-------+-------+-------+
```

| บิต | ชื่อเต็ม | ความหมายและหน้าที่ |
| :---: | :--- | :--- |
| **`CY` (PSW.7)** | **Carry Flag** | เป็น `1` เมื่อเกิดตัวทด (Carry) หรือตัวยืม (Borrow) จากบิต 7 ในการบวกลบเลข หรือใช้เป็น Bit Accumulator |
| **`AC` (PSW.6)** | **Auxiliary Carry Flag** | เป็น `1` เมื่อเกิดตัวทดจากบิต 3 ข้ามไปบิต 4 (Half-Carry) ใช้สำหรับคำสั่งปรับค่าเลขฐานสิบ BCD (`DA A`) |
| **`F0` (PSW.5)** | **Flag 0** | แฟลกสารพัดประโยชน์ที่ผู้ใช้กำหนดค่าเองได้ตามต้องการ (`SETB F0` / `CLR F0`) |
| **`RS1, RS0` (PSW.4, PSW.3)** | **Register Bank Select** | **เลือกชุด Register Bank (0 ถึง 3):**<br>• `00` = Bank 0 (`00H - 07H`)<br>• `01` = Bank 1 (`08H - 0FH`)<br>• `10` = Bank 2 (`10H - 17H`)<br>• `11` = Bank 3 (`18H - 1FH`) |
| **`OV` (PSW.2)** | **Overflow Flag** | เป็น `1` เมื่อเกิดการล้นของเลขมีเครื่องหมาย (Signed Arithmetic Overflow เกินช่วง $-128$ ถึง $+127$) |
| **`UD` (PSW.1)** | **User-Defined / Reserved** | บิตสำรองสำหรับการใช้งานทั่วไป |
| **`P` (PSW.0)** | **Parity Flag** | ถูกตั้งค่าอัตโนมัติ: เป็น `1` ถ้าจำนวนบิต 1 ใน Accumulator เป็น **เลขคี่ (Odd)** และเป็น `0` ถ้าเป็น **เลขคู่ (Even)** |

### ข้อ 8: หน้าที่และกระบวนการทำงานของ Assembler

#### 🔴 โจทย์ที่จำออกมา (Red Text):
> **8. Assembler คืออะไร**

#### 🔵 บันทึกแนวทางของรุ่นพี่ (Blue Text):
> - ถูกใช้เพื่อแปลงภาษา Assembly เป็นรหัสเครื่อง หรือ object file นอกจากนี้ยังแสดงข้อผิดพลาด หากมี syntax error ในโปรแกรม

#### 🔍 วิเคราะห์สิ่งที่อาจารย์ต้องการวัดผล:
อาจารย์ต้องการทดสอบความเข้าใจ **Software Development Toolchain** สำหรับระบบสมองกลฝังตัว (Source File $\rightarrow$ Assembler $\rightarrow$ Object/Hex File & Listing File)

#### 🟢 คำตอบฉบับสมบูรณ์สำหรับใช้ในห้องสอบ (Official Answer):
- **Assembler (โปรแกรมแอสเซมเบลอร์):** คือโปรแกรมแปลภาษา (Translator Tool) ที่ทำหน้าที่แปลงซอร์สโค้ดภาษาแอสเซมบลี (`.asm` / `.src`) ซึ่งเขียนด้วยชุดคำสั่งช่วยจำ (Mnemonics & Operands เช่น `MOV`, `ADD`, `SJMP`) และ Assembler Directives (`ORG`, `EQU`, `DB`, `END`) ให้กลายเป็น **รหัสภาษาเครื่อง (Machine Code / Object File `.obj` หรือ Intel HEX `.hex`)** ที่ไมโครคอนโทรลเลอร์สามารถนำไปบรรจุลงในหน่วยความจำ ROM และประมวลผลได้โดยตรง
- **หน้าที่หลัก 3 ประการของ Assembler:**
  1. **Translation (การแปลคำสั่ง):** แปลง Mnemonics เป็น Binary Opcodes และแปลง Label/สัญลักษณ์ เป็นค่าแอดเดรสจริง (Absolute Memory Address)
  2. **Error Detection (การตรวจจับข้อผิดพลาด):** ตรวจสอบความถูกต้องตามไวยากรณ์ (Syntax Checking) เช่น การสะกดคำสั่งผิด, การกำหนดค่าเกินขนาดไบต์ (Out of Range Immediate), หรือการกระโดดไปยัง Label ที่ไม่มีอยู่จริง
  3. **Listing Generation (การสร้างไฟล์รายงาน `.lst`):** สร้างไฟล์รายงานที่จับคู่บรรทัดซอร์สโค้ดกับรหัสภาษาเครื่องและที่อยู่หน่วยความจำจริง พร้อมทั้งแสดงตารางระบุสัญลักษณ์ (Symbol Table) เพื่อช่วยในการดีบักระบบ

### คำสั่งที่ 1: `ORG 1000H`

- 🔴 **คำสั่งที่จำออกมา:** `ORG 1000H`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** `ข้อมูลจะถูกเก็บไว้ที่ตำแหน่งหน่วยความจำ 1000H`
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** **Assembler Directive** (คำสั่งสำหรับตัวแปลภาษา ไม่ใช่ Machine Instruction ของ CPU)
  - **ขนาดและคาบเวลา:** 0 Byte (ไม่สร้าง Opcode), 0 Machine Cycle
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  - `ORG` ย่อมาจาก **Origin** ทำหน้าที่สั่งให้ Assembler ตั้งค่าตัวนับตำแหน่งหน่วยความจำ (Location Counter) ไปที่แอดเดรส **`1000H`** ของ Program ROM
  - ทำให้คำสั่งหรือข้อมูลในบรรทัดถัดไป ถูกบันทึกลงในหน่วยความจำโปรแกรมเริ่มต้นที่ตำแหน่งแอดเดรส `1000H` เป็นต้นไป
- ⚠️ **จุดที่มักสับสน:** `ORG` ไม่ใช่คำสั่งที่ CPU ประมวลผล จึงไม่มีผลต่อแฟลกหรือรีจิสเตอร์ใดๆ ในฮาร์ดแวร์ขณะทำงาน

---

### คำสั่งที่ 2: `MOV A, R2`

- 🔴 **คำสั่งที่จำออกมา:** `MOV A, R2`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** `A <- R2`
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** Data Transfer Instruction
  - **Addressing Mode:** **Register Addressing**
  - **ขนาดและคาบเวลา:** 1 Byte (Opcode: `EAH` เมื่อใช้ Bank 0), ใช้เวลา **1 Machine Cycle**
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  - คัดลอกข้อมูลขนาด 8 บิตจากรีจิสเตอร์ $R_2$ ของ Register Bank ที่กำลังถูกเลือกอยู่ในขณะนั้น (Active Register Bank) เข้าไปเก็บไว้ใน Accumulator ($A$)
  - ข้อมูลเดิมใน $R_2$ ยังคงมีค่าเท่าเดิมไม่เปลี่ยนแปลง ($A \leftarrow R_2$)
- 🚩 **ผลต่อ Status Flags:** ไม่มีผลต่อแฟลก `CY`, `AC`, `OV` (ยกเว้น Parity Flag `P` ที่จะปรับค่าตามจำนวนบิต 1 ใน A เสมอ)
- 💡 **ตัวอย่างการ Trace:**
  - *ก่อนรัน:* $A = 00\text{H}, \ R_2 = 45\text{H}$
  - *หลังรัน:* $A = 45\text{H}, \ R_2 = 45\text{H}, \ P = 0$ (เพราะ $45\text{H} = 0100\ 0101_2$ มีเลข 1 อยู่ 3 ตัว $\rightarrow$ เลขคี่ $P = 1$)

---

### คำสั่งที่ 3: `MOV A, 35H`

- 🔴 **คำสั่งที่จำออกมา:** `MOV A, 35H`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** `A <- [35H]`
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** Data Transfer Instruction
  - **Addressing Mode:** **Direct Addressing**
  - **ขนาดและคาบเวลา:** 2 Bytes (Opcode: `E5 35`), ใช้เวลา **1 Machine Cycle**
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  - นำข้อมูลขนาด 8 บิตที่เก็บอยู่ใน Internal RAM ตำแหน่งแอดเดรส **`35H`** (โซน General-Purpose RAM) มาเก็บไว้ใน Accumulator ($A$) ($A \leftarrow \text{RAM}[35\text{H}]$)
- ⚠️ **จุดเน้นสำคัญในห้องสอบ:**
  - เนื่องจาก **ไม่มีเครื่องหมาย `#`** ตัวเลข `35H` จึงทำหน้าที่เป็น **Direct Memory Address** ไม่ใช่ค่าคงที่!
  - เปรียบเทียบ: `MOV A, #35H` (นำค่า $35\text{H}$ ใส่ A) $\neq$ `MOV A, 35H` (นำข้อมูลที่อยู่ใน RAM ช่อง 35H ใส่ A)

---

### คำสั่งที่ 4: `MOV A, @R1`

- 🔴 **คำสั่งที่จำออกมา:** `MOV A, @R1`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** `A <- [R1]`
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** Data Transfer Instruction
  - **Addressing Mode:** **Indirect Addressing (การอ้างแอดเดรสทางอ้อม)**
  - **ขนาดและคาบเวลา:** 1 Byte (Opcode: `E7H`), ใช้เวลา **1 Machine Cycle**
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  - ใช้ค่าที่เก็บอยู่ในรีจิสเตอร์ $R_1$ เป็น **Address Pointer** ชี้ไปยังตำแหน่งแอดเดรสใน Internal RAM แล้วนำข้อมูลที่ตำแหน่งนั้นมาใส่ใน Accumulator ($A$) ($A \leftarrow \text{RAM}[[R_1]]$)
- 💡 **ตัวอย่างการ Trace:**
  - *ก่อนรัน:* $R_1 = 40\text{H}$, ใน Internal RAM แอดเดรส $40\text{H}$ มีข้อมูล $= 88\text{H}$
  - *หลังรัน:* $A = 88\text{H}$ (ค่าใน $R_1$ ยังคงเป็น $40\text{H}$ เหมือนเดิม)
- ⚠️ **กฎของ 8051:** รีจิสเตอร์ที่ใช้ทำ Indirect Addressing สำหรับ Internal RAM ได้มีเพียง **`R0` และ `R1`** เท่านั้น (ใช้ `R2 - R7` ไม่ได้)

---

### คำสั่งที่ 5: `ADD A, #50H`

- 🔴 **คำสั่งที่จำออกมา:** `ADD A, #50H`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** `A <- A + 50H`
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** Arithmetic Instruction (Addition)
  - **Addressing Mode:** **Immediate Addressing**
  - **ขนาดและคาบเวลา:** 2 Bytes (Opcode: `04 50`), ใช้เวลา **1 Machine Cycle**
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  - นำค่าคงที่ขนาด 8 บิตคือ **`50H`** (เท่ากับ $80_{10}$) ไปบวกเข้ากับค่าเดิมใน Accumulator ($A$) แล้วนำผลลัพธ์ที่ได้ไปเก็บทับใน Accumulator ($A \leftarrow A + 50\text{H}$)
- 🚩 **ผลต่อ Status Flags ใน PSW:**
  - `CY` (Carry): เป็น `1` หากผลบวกเกิน 8 บิต (มีตัวทดจากบิต 7)
  - `AC` (Auxiliary Carry): เป็น `1` หากเกิดตัวทดจากบิต 3 ข้ามไปบิต 4 (Half-Carry)
  - `OV` (Overflow): เป็น `1` หากเกิดการล้นของเลขมีเครื่องหมาย (Signed Overflow)
  - `P` (Parity): อัปเดตตามจำนวนบิต 1 ใน A หลังการคำนวณ

---

### คำสั่งที่ 6: `SUBB A, R1`

- 🔴 **คำสั่งที่จำออกมา:** `SUBB A, R1`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** `A <- A - R1 - Carry`
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** Arithmetic Instruction (Subtract with Borrow)
  - **Addressing Mode:** **Register Addressing**
  - **ขนาดและคาบเวลา:** 1 Byte (Opcode: `99H`), ใช้เวลา **1 Machine Cycle**
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  - นำค่าใน Accumulator ($A$) ตั้ง แล้วลบด้วยค่าในรีจิสเตอร์ $R_1$ และ **ลบด้วยค่าของ Carry Flag ($CY$)** จากนั้นนำผลลัพธ์ไปเก็บใน Accumulator ($A \leftarrow A - R_1 - CY$)
- 🚩 **ผลต่อ Status Flags:**
  - `CY`: เป็น `1` หากเกิดการขอยืมบิต (Borrow) ที่บิต 7 (เช่น ตัวตั้งน้อยกว่าตัวลบ)
  - `AC`: เป็น `1` หากเกิดการขอยืมบิตที่บิต 3
  - `OV`: เป็น `1` หากเกิด Signed Underflow/Overflow
- ⚠️ **กฎสำคัญ:** ใน 8051 **ไม่มีคำสั่ง `SUB` ธรรมดา** มีเฉพาะ `SUBB` เท่านั้น หากต้องการลบเลขธรรมดาโดยไม่เอาตัวทดเดิมมาลบ ต้องใส่คำสั่ง **`CLR C`** ก่อนเรียกใช้ `SUBB` เสมอ!

---

### คำสั่งที่ 7: `INC 25H`

- 🔴 **คำสั่งที่จำออกมา:** `INC 25H`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** `[25H] <- [25H] + 1`
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** Arithmetic Instruction (Increment)
  - **Addressing Mode:** **Direct Addressing**
  - **ขนาดและคาบเวลา:** 2 Bytes (Opcode: `05 25`), ใช้เวลา **1 Machine Cycle**
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  - เพิ่มค่าของข้อมูลที่เก็บอยู่ใน Internal RAM ตำแหน่งแอดเดรส **`25H`** ขึ้นอีก 1 ($\text{RAM}[25\text{H}] \leftarrow \text{RAM}[25\text{H}] + 1$)
- 🚩 **ข้อพึงระวังเรื่อง Flags:** คำสั่ง `INC` ทุกรูปแบบ (รวมถึง `INC A`, `INC Rn`, `INC DPTR`) **ไม่มีผลกระทบต่อ Carry Flag (`CY`) เลย** แม้ว่าค่าเดิมจะเป็น `FFH` แล้วบวก 1 วนกลับมาเป็น `00H` ก็ตาม

### คำสั่งที่ 8: `ANL C, P0.2`

- 🔴 **คำสั่งที่จำออกมา:** `ANL C, P0.2`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** `C <- C AND P0.2`
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** Boolean / Bit-Manipulation Instruction
  - **Addressing Mode:** **Bit Addressing (Direct Bit Addressing)**
  - **ขนาดและคาบเวลา:** 2 Bytes (Opcode: `82 82`), ใช้เวลา **2 Machine Cycles**
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  - อ่านสถานะลอจิก (0 หรือ 1) จากขาพอร์ต 0 บิตที่ 2 (`P0.2` ซึ่งอยู่ที่ Bit Address `82H`) แล้วนำมาทำลอจิก **AND** ร่วมกับค่าเดิมใน Carry Flag ($C$) จากนั้นบันทึกผลลัพธ์ลงใน Carry Flag ($C \leftarrow C \land \text{P0.2}$)
- 💡 **การนำไปใช้งาน:** ใช้สำหรับรวมเงื่อนไขลอจิกของสวิตช์หรือสัญญาณภายนอกเข้าสู่ Carry Flag เพื่อใช้คำสั่งตัดสินใจกระโดดแบบมีเงื่อนไข เช่น `JC` (Jump if Carry) หรือ `JNC` (Jump if No Carry)

### คำสั่งที่ 9: `DJNZ 25H, Label`

- 🔴 **คำสั่งที่จำออกมา:** `DJNZ 25H, Label`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** *(ในไฟล์รุ่นพี่ไม่ได้เขียนอธิบายไว้)*
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** Program Branching / Loop Control Instruction
  - **Addressing Mode:** **Direct Addressing + Relative Addressing**
  - **ขนาดและคาบเวลา:** 3 Bytes (Opcode: `D5 25 rel`), ใช้เวลา **2 Machine Cycles**
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  1. ลดค่าของข้อมูลใน Internal RAM ตำแหน่งแอดเดรส `25H` ลง 1 ($\text{RAM}[25\text{H}] \leftarrow \text{RAM}[25\text{H}] - 1$)
  2. ตรวจสอบเงื่อนไข:
     - ถ้าค่าหลังลด **ยังไม่เป็นศูนย์ ($\text{RAM}[25\text{H}] \neq 0$)** ให้กระโดดไปยังตำแหน่ง **`Label`**
     - ถ้าค่าหลังลด **กลายเป็นศูนย์ ($\text{RAM}[25\text{H}] = 0$)** ให้โปรแกรมทำงานต่อที่คำสั่งในบรรทัดถัดไปตามปกติ (หลุดจาก Loop)
- 💡 **การนำไปใช้งาน:** เป็นคำสั่งหัวใจหลักในการสร้าง Loop นับรอบและฟังก์ชันหน่วงเวลา (Software Delay Routine)

### คำสั่งที่ 10: `SJMP Label`

- 🔴 **คำสั่งที่จำออกมา:** `SJMP Label`
- 🔵 **บันทึกแนวทางของรุ่นพี่:** *(ในไฟล์รุ่นพี่ไม่ได้เขียนอธิบายไว้)*
- 📋 **รายละเอียดเชิงสถาปัตยกรรม:**
  - **ประเภท:** Unconditional Branching (Short Jump)
  - **Addressing Mode:** **Relative Addressing (การอ้างตำแหน่งแบบสัมพัทธ์)**
  - **ขนาดและคาบเวลา:** 2 Bytes (Opcode: `80 rel`), ใช้เวลา **2 Machine Cycles**
- 🟢 **คำอธิบายการทำงานฉบับสมบูรณ์:**
  - สั่งให้ Program Counter (PC) กระโดดไปยังตำแหน่ง `Label` โดยใช้ค่าระยะทางสัมพัทธ์ (Relative Offset) ขนาด 8 บิต แบบ Two's Complement
  - สามารถกระโดดได้ในระยะ **$-128$ ไบต์ (ถอยหลัง) ถึง $+127$ ไบต์ (เดินหน้า)** นับจากตำแหน่งของคำสั่งถัดไป
  - สูตร: $\text{Target Address} = \text{PC of Next Instruction} + \text{Relative Offset}$
- 💡 **ข้อดี:** ใช้พื้นที่หน่วยความจำเพียง 2 ไบต์ (ประหยัดกว่า `LJMP` ที่ใช้ 3 ไบต์) และทำให้โค้ดสามารถย้ายตำแหน่งใน ROM ได้ง่าย (Relocatable Code)

# ตารางสรุป Addressing Modes และ Memory Map สำหรับห้องสอบ

### 1. สรุป Addressing Modes ของ 8051 ทั้ง 5 รูปแบบ

| รูปแบบ (Addressing Mode) | สัญลักษณ์ / จุดสังเกต | ตัวอย่างคำสั่ง | ความหมายเชิงลึก |
| :--- | :---: | :--- | :--- |
| **1. Immediate** | มีเครื่องหมาย `#` | `MOV A, #25H` | โหลด **ค่าคงที่ 25H** ใส่ใน A ทันที |
| **2. Register** | ระบุชื่อ $R_0 - R_7$, $A$, $B$ | `MOV A, R3` | ย้ายข้อมูลจาก **รีจิสเตอร์ $R_3$** (Bank ปัจจุบัน) ไป A |
| **3. Direct** | ระบุตัวเลข Address หรือชื่อ SFR | `MOV A, 30H` | ย้ายข้อมูลจาก **Internal RAM ที่อยู่ 30H** ไป A |
| **4. Indirect** | มีเครื่องหมาย `@` นำหน้า Pointer | `MOV A, @R0` | ย้ายข้อมูลจาก **แอดเดรสที่ $R_0$ ชี้อยู่** ไป A |
| **5. Indexed** | ใช้ `@A+DPTR` หรือ `@A+PC` | `MOVC A, @A+DPTR` | อ่านค่าคงที่จาก **Program ROM** ที่ตำแหน่ง $\text{A}+\text{DPTR}$ |

---

### 2. สรุปแผนผังหน่วยความจำ Internal Data RAM (128 Bytes: `00H - 7FH`)

```text
+---------------+ 7FH
|               |
| General-      | (80 Bytes)
| Purpose RAM   | สำหรับเก็บตัวแปรทั่วไป และเป็นพื้นที่ของ Stack
| (Scratchpad)  |
|               |
+---------------+ 30H
+---------------+ 2FH
| Bit-Addressable| (16 Bytes = 128 Bits: แอดเดรสบิต 00H ถึง 7FH)
| RAM           | เข้าถึงระดับบิตได้ด้วยคำสั่ง SETB, CLR, JB, JNB
+---------------+ 20H
+---------------+ 1FH
| Reg Bank 3    | R0 - R7 (แอดเดรส 18H - 1FH)
+---------------+ 17H
| Reg Bank 2    | R0 - R7 (แอดเดรส 10H - 17H)
+---------------+ 0FH
| Reg Bank 1    | R0 - R7 (แอดเดรส 08H - 0FH)
+---------------+ 07H
| Reg Bank 0    | R0 - R7 (แอดเดรส 00H - 07H) -> ค่าเริ่มต้นหลัง RESET
+---------------+ 00H
```

### 3. Checklist เตรียมพร้อมก่อนเข้าห้องสอบ
1. **แยกความหมายของ `#` ให้ออก:** `MOV A, #80H` (ใส่ค่า 80H) $\neq$ `MOV A, 80H` (อ่านค่าจากพอร์ต P0/SFR 80H)
2. **เข้าใจ Harvard vs Von Neumann:** 8051 เป็น Harvard แยก Program ROM (`MOVC`) ออกจาก Data RAM (`MOVX`)
3. **จำโครงสร้าง PSW ให้แม่น:** `RS1:RS0` (`00`=Bank 0, `01`=Bank 1, `10`=Bank 2, `11`=Bank 3), `CY`, `AC`, `OV`, `P`
4. **คำนวณ Machine Cycle:** $1 \text{ Machine Cycle} = 12 \text{ Oscillator Clocks} \rightarrow T = \frac{12}{f_{\text{osc}}}$
5. **คำสั่งคูณหาร 8051:** `MUL AB` (High byte ใน B, Low byte ใน A), `DIV AB` (ผลหารใน A, เศษใน B)
