ข้อ 1

ความหมายและองค์ประกอบของ Embedded System

Lecture 1 (สไลด์ 3-8)
โจทย์ที่รุ่นพี่จำออกมา (ข้อความสีแดง):
1. Embedded System คืออะไร มีองค์ประกอบอะไรบ้าง
แนวทางคำตอบของรุ่นพี่ (ข้อความสีฟ้า - Draft):
  • Microcontroller หรือระบบที่ใช้ microprocessor ที่ออกแบบมาทำงานเฉพาะอย่าง
  • มี 3 องค์ประกอบ คือ 1. Hardware 2. Application Software 3. Real Time Operating System (RTOS)
เฉลยฉบับสมบูรณ์สำหรับใช้ตอบข้อสอบจริง (Official Answer)
คะแนนเต็ม 100%

1. นิยามของ Embedded System (ระบบสมองกลฝังตัว):
คือระบบคอมพิวเตอร์ (ที่ใช้ Microcontroller หรือ Microprocessor) ซึ่งถูกสร้างหรือ ฝังตัวอยู่ภายในผลิตภัณฑ์หรือระบบขนาดใหญ่ เพื่อทำหน้าที่ควบคุม ประมวลผล หรือทำงาน เฉพาะทางอย่างใดอย่างหนึ่งโดยเฉพาะ (Dedicated / Single-purpose Function) มักทำงานแบบเวลาจริง (Real-Time System) ที่ผลลัพธ์ต้องถูกต้องและทันเวลา (Deadline) ภายใต้ข้อจำกัดด้านทรัพยากร (พลังงาน, ขนาด, หน่วยความจำ, และต้นทุน)

2. องค์ประกอบหลัก 3 ส่วน (Building Blocks):

  1. ฮาร์ดแวร์ (Hardware): ชิปประมวลผล (MCU เช่น 8051), หน่วยความจำ (ROM/Flash เก็บโปรแกรม, RAM เก็บข้อมูล), พอร์ต I/O, ตัวนับเวลา (Timers), วงจรขัดจังหวะ (Interrupts), เซนเซอร์ (Sensors) และตัวขับกำลัง (Actuators)
  2. ซอฟต์แวร์ประยุกต์ (Application Software / Firmware):** ชุดคำสั่งโปรแกรมที่พัฒนาขึ้นมาเฉพาะทาง (เขียนด้วย Assembly หรือ C) เพื่อควบคุมลอจิกการทำงานของอุปกรณ์
  3. ระบบปฏิบัติการเวลาจริง (RTOS) / System Control:** ซอฟต์แวร์ระบบที่ทำหน้าที่บริหารจัดการ Task Scheduling, Timing, และตอบสนองต่อ Event ได้อย่างแม่นยำ (ในระบบขนาดเล็กอาจรันแบบ Bare-metal / Super-loop)
ไดอะแกรม Building Blocks of Embedded System (Lecture 1)
จุดที่มักโดนหักคะแนน / ข้อจำกัดของแนวคิดรุ่นพี่:
การเขียนตอบเพียงชื่อองค์ประกอบ 1-2-3 โดยไม่อธิบายขยายความหน้าที่ของ Hardware, Software, และ RTOS จะทำให้เสียคะแนนอธิบาย ควรระบุหน้าที่สั้นๆ ของแต่ละองค์ประกอบเสมอ
ข้อ 2

เปรียบเทียบ Microprocessor กับ Microcontroller

Lecture 1 (สไลด์ 9-14)
โจทย์ที่รุ่นพี่จำออกมา (ข้อความสีแดง):
2. Microprocessor และ Microcontroller แตกต่างกันอย่างไร
แนวทางคำตอบของรุ่นพี่ (ข้อความสีฟ้า - Draft):
  • Microprocessor มีความยืดหยุ่นมากกว่า ใช้สำหรับวัตถุประสงค์ทั่วไป
  • Microcontroller มีความยืดหยุ่นน้อยกว่า ออกแบบมาเพื่อทำงานเฉพาะอย่าง จำเป็นต้องมีการทำงานเฉพาะอย่าง
เฉลยฉบับสมบูรณ์สำหรับใช้ตอบข้อสอบจริง (Official Answer)
ตารางเปรียบเทียบ 6 มิติ

ควรตอบในรูปแบบตารางเปรียบเทียบโครงสร้างฮาร์ดแวร์และการนำไปใช้งานจริง:

มิติการเปรียบเทียบ Microprocessor (MPU) Microcontroller (MCU)
1. โครงสร้างชิป (Architecture) มีเฉพาะ CPU Only (ALU, CU, Registers) ไม่มี RAM, ROM, I/O บนชิป เป็น Single-Chip Computer รวม CPU, RAM, ROM/Flash, I/O, Timers, Interrupts ไว้ในชิปเดียว
2. การต่อใช้งาน (System Connection) ต้องต่อชิปภายนอกเพิ่ม (External RAM, ROM, I/O Controller) ผ่าน Bus มีอุปกรณ์ต่อพ่วงเบ็ดเสร็จในตัว ไม่จำเป็นต้องต่อชิปภายนอกเพิ่ม
3. วัตถุประสงค์ (Application) General-Purpose (คอมพิวเตอร์ PC, Laptop, Server รันโปรแกรมหลากหลาย) Dedicated / Embedded Control (เครื่องซักผ้า, แอร์, รีโมท, ECU รถยนต์)
4. ความยืดหยุ่น (Flexibility) ยืดหยุ่นสูง สามารถเพิ่ม/เปลี่ยนขนาด RAM, SSD, การ์ดจอได้ตามต้องการ สเปกคงที่ ขนาด RAM, ROM, ขา I/O ถูกกำหนดตายตัวตามเบอร์ชิป
5. การใช้พลังงาน & ขนาด ใช้ไฟสูง (หลายวัตต์ถึงร้อยวัตต์) เกิดความร้อนสูง บอร์ดขนาดใหญ่ กินไฟต่ำมาก (หลักมิลลิวัตต์/ไมโครแอมป์) ทำงานด้วยแบตเตอรี่ได้ ขนาดเล็ก
6. ต้นทุนระบบรวม ต้นทุนรวมสูงเนื่องจากต้องใช้อุปกรณ์เสริมภายนอกหลายชิ้น ต้นทุนต่อหน่วยต่ำมาก เหมาะกับการผลิตเชิงอุตสาหกรรมจำนวนมาก
โครงสร้างภายใน Single-Chip Microcontroller 8051 (Lecture 1)
จุดที่มักโดนหักคะแนน:
หากตอบแค่ "MPU ยืดหยุ่นกว่า / MCU ทำเฉพาะทาง" จะได้คะแนนเพียง 2-3 ส่วนจาก 10 คะแนนเต็ม ต้องเน้นเรื่อง CPU Only vs Single-Chip Computer รวมหน่วยความจำและพอร์ต เสมอ!
ข้อ 3

เปรียบเทียบสถาปัตยกรรม Von Neumann กับ Harvard

Lecture 1 (สไลด์ 15-20)
โจทย์ที่รุ่นพี่จำออกมา (ข้อความสีแดง):
3. Von Neumann และ Harvard แตกต่างกันอย่างไร
แนวทางคำตอบของรุ่นพี่ (ข้อความสีฟ้า - Draft):
  • Von Neumann : data และ code อยู่ในหน่วยความจำเดียวกัน, มีการออกแบบเรียบง่าย, pipelining not possible, 2 set of clocks cycles ( 1 รอบ สำหรับ การดึงข้อมูล, 1 รอบ สำหรับ การดึงคำสั่ง)
  • Harvard : data และ code อยู่ในหน่วยความจำที่แตกต่างกัน, มีความซับซ้อนในการออกแบบ, pipelining is possible, single clock cycle (สำหรับการดึงข้อมูล และการดึงคำสั่ง)
เฉลยฉบับสมบูรณ์สำหรับใช้ตอบข้อสอบจริง (Official Answer)
สถาปัตยกรรมบัสและหน่วยความจำ

1. Von Neumann Architecture (สถาปัตยกรรมวอนนอยมันน์):

  • โครงสร้างหน่วยความจำ: ใช้พื้นที่หน่วยความจำร่วมกัน (Unified Memory Space) เก็บทั้งโปรแกรมคำสั่ง (Code) และข้อมูล (Data)
  • ระบบบัส: ใช้ Address Bus และ Data Bus ร่วมกันเพียงชุดเดียว
  • ข้อจำกัด: เกิดภาวะคอขวด (Von Neumann Bottleneck) ไม่สามารถดึงคำสั่ง (Fetch) และอ่าน/เขียนข้อมูล (Data Access) พร้อมกันใน Clock เดียวกันได้ ต้องใช้สัญญาณนาฬิกาอย่างน้อย 2 รอบ
  • ข้อดี: วงจรออกแบบง่าย สายสัญญาณน้อย ต้นทุนต่ำ

2. Harvard Architecture (สถาปัตยกรรมฮาร์วาร์ด):

  • โครงสร้างหน่วยความจำ: แยกหน่วยความจำสำหรับเก็บคำสั่ง (Program/Code ROM) ออกจากหน่วยความจำเก็บข้อมูล (Data RAM) อย่างเด็ดขาด
  • ระบบบัส: มี Address Bus และ Data Bus แยกกันคนละชุด (Code Bus และ Data Bus)
  • ข้อดี: CPU สามารถอ่าน/เขียนข้อมูลพร้อมกับดึงคำสั่งถัดไปได้พร้อมกันในรอบสัญญาณนาฬิกาเดียวกัน (Simultaneous Access / Single Clock Cycle) รองรับ Pipelining ได้อย่างสมบูรณ์
  • การนำไปใช้งาน: ไมโครคอนโทรลเลอร์ MCS-51 / 8051 ใช้โครงสร้าง Modified Harvard Architecture
ไดอะแกรมเปรียบเทียบสถาปัตยกรรมบัส Von Neumann vs Harvard (Lecture 1)
ข้อ 4

ขนาดหน่วยความจำ Internal ROM และ Internal RAM ใน 8051

Lecture 2 & 3
โจทย์ที่รุ่นพี่จำออกมา (ข้อความสีแดง):
4. Internal ROM และ Internal RAM มีขนาดเท่าไหร่
แนวทางคำตอบของรุ่นพี่ (ข้อความสีฟ้า - Draft):
  • Internal ROM มีขนาด 4 Kbyte
  • Internal RAM มีขนาด 128 byte
เฉลยฉบับสมบูรณ์สำหรับใช้ตอบข้อสอบจริง (Official Answer)
Memory Organization & Address Map

1. Internal Program ROM (หน่วยความจำโปรแกรมภายใน):
มีขนาด 4 Kbytes อยู่ที่ช่วงแอดเดรส 0000H ถึง 0FFFH (ควบคุมการเปิดใช้งานด้วยขา EA: ถ้า EA = 1 อ่านจาก ROM ภายในก่อน, ถ้า EA = 0 อ่านจาก ROM ภายนอกทั้งหมด)

2. Internal Data RAM (หน่วยความจำข้อมูลภายใน):
มีขนาด 128 Bytes อยู่ที่ช่วงแอดเดรส 00H ถึง 7FH โดยแบ่งเป็น 3 โซนหลัก:

  • 00H - 1FH (32 Bytes): Register Banks 4 ชุด (Bank 0, 1, 2, 3) แต่ละ Bank มีรีจิสเตอร์ R0 - R7 รวม 8 ตัว
  • 20H - 2FH (16 Bytes): Bit-Addressable RAM รองรับการเข้าถึงระดับบิตได้ 128 บิต (บิตแอดเดรส 00H - 7FH)
  • 30H - 7FH (80 Bytes): General-Purpose RAM (Scratchpad) สำหรับเก็บตัวแปรทั่วไปและใช้เป็นพื้นที่ของ Stack

(หมายเหตุ: ถ้าเป็นชิป 8052 จะมี RAM ภายใน 256 Bytes โดยช่วง 80H - FFH ด้านบนเข้าถึงผ่าน Indirect Addressing @R0/@R1)

โครงสร้างการแบ่งพื้นที่ Internal Data RAM 128 Bytes (Lecture 3)
ข้อ 5

จำนวนและลักษณะของพอร์ต I/O บน 8051

Lecture 2 (สไลด์ 15-22)
โจทย์ที่รุ่นพี่จำออกมา (ข้อความสีแดง):
5. Microcontroller 8051 มีทั้งหมดกี่พอร์ต
แนวทางคำตอบของรุ่นพี่ (ข้อความสีฟ้า - Draft):
  • 4 port (P0 – P3)
เฉลยฉบับสมบูรณ์สำหรับใช้ตอบข้อสอบจริง (Official Answer)
32 I/O Pins & Alternate Functions

ไมโครคอนโทรลเลอร์ 8051 มีพอร์ต I/O ทั้งหมด 4 พอร์ต (Port 0 – Port 3) แต่ละพอร์ตมีขนาด 8 บิต รวมทั้งหมด 32 ขา I/O โดยมีคุณสมบัติเฉพาะดังนี้:

  • Port 0 (P0.0 - P0.7, SFR 80H): เป็นพอร์ตแบบ Open-Drain (ไม่มี Pull-up ในตัว ต้องต่อตัวต้านทาน Pull-up ภายนอกเมื่อใช้เป็น I/O) และทำหน้าที่เป็น Multiplexed Address/Data Bus (AD0 - AD7) เมื่อต่อ External Memory
  • Port 1 (P1.0 - P1.7, SFR 90H): เป็นพอร์ต Quasi-Bidirectional มี Internal Pull-up ในตัว ใช้เป็น General I/O ทั่วไป
  • Port 2 (P2.0 - P2.7, SFR A0H): เป็นพอร์ต Quasi-Bidirectional ทำหน้าที่ส่ง High-order Address Bus (A8 - A15) เมื่อต่อหน่วยความจำภายนอก
  • Port 3 (P3.0 - P3.7, SFR B0H): เป็นพอร์ต Quasi-Bidirectional ที่มี หน้าที่พิเศษรอง (Alternate Functions):
    • P3.0 (RxD) / P3.1 (TxD): รับ-ส่งข้อมูลอนุกรม (Serial Port)
    • P3.2 (INT0) / P3.3 (INT1): สัญญาณขัดจังหวะภายนอก (External Interrupts)
    • P3.4 (T0) / P3.5 (T1): สัญญาณนับเวลาภายนอก (Timer/Counter Inputs)
    • P3.6 (WR) / P3.7 (RD): สัญญาณควบคุมอ่าน/เขียนหน่วยความจำข้อมูลภายนอก
โครงสร้างขาและพอร์ต I/O ของ 8051 40-pin DIP (Lecture 2)
ข้อ 6

หน้าที่และลักษณะของ Register B

Lecture 2 & 4
โจทย์ที่รุ่นพี่จำออกมา (ข้อความสีแดง):
6. Register B คืออะไร
แนวทางคำตอบของรุ่นพี่ (ข้อความสีฟ้า - Draft):
  • เป็น register 8 bit มีไว้สำหรับการคูณ และการหาร
เฉลยฉบับสมบูรณ์สำหรับใช้ตอบข้อสอบจริง (Official Answer)
SFR Address F0H & Math Operations

Register B เป็นรีจิสเตอร์ฟังก์ชันพิเศษ (SFR ขนาด 8 บิต) อยู่ที่แอดเดรส F0H (เข้าถึงระดับบิตได้ / Bit-addressable) ใช้งานหลักคู่กับ Accumulator (A) ในการคำนวณคณิตศาสตร์:

  • คำสั่งคูณ MUL AB: นำค่า A × B ผลคูณขนาด 16 บิตจะถูกเก็บโดย:
    • High Byte (ไบต์บน) → เก็บใน Register B
    • Low Byte (ไบต์ล่าง) → เก็บใน Accumulator A
    • (ถ้าผลคูณ > 255 แฟลก OV = 1)
  • คำสั่งหาร DIV AB: นำค่า A ÷ B:
    • ผลหาร (Quotient) → เก็บใน Accumulator A
    • เศษเหลือ (Remainder) → เก็บใน Register B
    • (ถ้า B = 0 แฟลก OV = 1 เตือนหารด้วยศูนย์)
  • การใช้งานทั่วไป: เมื่อไม่ได้ใช้ในการคูณหาร สามารถใช้ Register B เป็นที่พักข้อมูลชั่วคราว (General Storage Register) ได้

7. PSW มีชื่อเต็มว่าอะไร
แนวทางคำตอบของรุ่นพี่ (ข้อความสีฟ้า - Draft):
  • Program Status Word (PSW)
เฉลยฉบับสมบูรณ์สำหรับใช้ตอบข้อสอบจริง (Official Answer)
SFR D0H & 8 Status Bits

ชื่อเต็ม: Program Status Word (PSW)
เป็นรีจิสเตอร์ SFR ขนาด 8 บิต อยู่ที่แอดเดรส D0H (Bit-addressable) ทำหน้าที่เก็บสถานะของ ALU หลังการประมวลผลคำสั่ง:

ชื่อบิต ความหมายเต็ม หน้าที่และการทำงาน
CY (PSW.7) Carry Flag เป็น 1 เมื่อเกิดตัวทด/ตัวยืมจากบิต 7 ในการบวกลบเลข หรือใช้เป็น Bit Accumulator
AC (PSW.6) Auxiliary Carry Flag เป็น 1 เมื่อเกิดตัวทดจากบิต 3 ไปบิต 4 (Half-carry) สำหรับคำสั่งปรับค่า BCD (DA A)
F0 (PSW.5) Flag 0 แฟลกสารพัดประโยชน์ที่ผู้ใช้กำหนดค่าเองได้ (SETB F0 / CLR F0)
RS1, RS0 (PSW.4, 3) Register Bank Select เลือก Bank 0-3: 00=Bank 0 (00-07H), 01=Bank 1 (08-0FH), 10=Bank 2 (10-17H), 11=Bank 3 (18-1FH)
OV (PSW.2) Overflow Flag เป็น 1 เมื่อเกิดการล้นของเลขมีเครื่องหมาย (Signed Overflow เกินช่วง -128 ถึง +127)
UD (PSW.1) User-defined / Reserved บิตสำรองสำหรับการใช้งานทั่วไป
P (PSW.0) Parity Flag เป็น 1 ถ้าจำนวนบิต 1 ใน Accumulator เป็น เลขคี่ (Odd) และเป็น 0 ถ้าเป็น เลขคู่ (Even)
โครงสร้างบิตใน PSW Register (Lecture 2)

8. Assembler คืออะไร
แนวทางคำตอบของรุ่นพี่ (ข้อความสีฟ้า - Draft):
  • ถูกใช้เพื่อแปลงภาษา Assembly เป็นรหัสเครื่อง หรือ object file นอกจากนี้ยังแสดงข้อผิดพลาด หากมี syntax error ในโปรแกรม
เฉลยฉบับสมบูรณ์สำหรับใช้ตอบข้อสอบจริง (Official Answer)
Software Toolchain & Code Generation

Assembler (โปรแกรมแอสเซมเบลอร์): คือโปรแกรมแปลภาษาที่ทำหน้าที่แปลงซอร์สโค้ดภาษาแอสเซมบลี (.asm / .src) ซึ่งเขียนด้วยคำสั่งช่วยจำ (Mnemonics & Operands เช่น MOV, ADD) และ Assembler Directives (ORG, EQU, END) ให้กลายเป็น รหัสภาษาเครื่อง (Machine Code / Object File .obj หรือ Intel HEX .hex) ที่ชิป MCU สามารถโหลดลง ROM ไปประมวลผลได้

หน้าที่หลัก 3 ประการ:

  1. Translation: แปลง Mnemonics เป็น Binary Opcodes และแปลง Label เป็น Memory Address จริง
  2. Syntax Error Checking: ตรวจสอบความถูกต้องของไวยากรณ์คำสั่งและช่วงของค่าคงที่
  3. Listing File Generation: สร้างไฟล์รายงาน .lst แสดงตารางจับคู่ระหว่างบรรทัดซอร์สโค้ด, รหัสภาษาเครื่อง, แอดเดรส และ Symbol Table สำหรับการดีบัก
แผนภาพกระบวนการ Software Toolchain (Lecture 4)

คำสั่งที่ 1

ORG 1000H

Assembler Directive / Location Counter
คำสั่งในข้อสอบ:
ORG 1000H
แนวทางของรุ่นพี่ (สั้นเกินไป):
"ข้อมูลจะถูกเก็บไว้ที่ตำแหน่งหน่วยความจำ 1000H" — (ข้อวิเคราะห์: ไม่ถูกต้องสมบูรณ์ เพราะ ORG ไม่ใช่คำสั่งย้ายข้อมูล และทำงานกับ Program ROM ไม่ใช่ RAM)
คำตอบที่ควรเขียนในกระดาษคำตอบห้องสอบ (Exam Answer - ได้คะแนนเต็ม 100%)

คำอธิบายการทำงาน: เป็นคำสั่งกำหนดทิศทางของตัวแปลภาษา (Assembler Directive / Pseudo-instruction) โดยสั่งให้ตัวนับตำแหน่ง (Location Counter / Program Counter) เริ่มต้นวางรหัสภาษาเครื่อง (Machine Code) ของคำสั่งในบรรทัดถัดไปลงในหน่วยความจำโปรแกรม (Program Memory / ROM) เริ่มต้นที่แอดเดรส 1000H (สัญลักษณ์ RTL: Location Counter ← 1000H)

การวิเคราะห์ทางสถาปัตยกรรมและฮาร์ดแวร์เชิงลึก:
ประเภทคำสั่ง Assembler Directive (คำสั่งควบคุมตัวแปลภาษา) ไม่ใช่คำสั่งที่ CPU Execute ในขณะทำงานจริง
ขนาด / รอบเวลา 0 Byte (ไม่สร้างรหัส Opcode ลง ROM), 0 Machine Cycle (ไม่มีเวลาหน่วง)
ผลต่อธงใน PSW ไม่มีผลต่อ Flag ใดๆ (CY, AC, OV, P คงเดิมทั้งหมด)
ผลเชิงสถาปัตยกรรม ตัว Assembler จะปรับค่า Offset Pointer ของไฟล์ Intel HEX ให้เรคคอร์ดถัดไปถูกเขียนที่ Address 1000H
ข้อควรระวังและจุดตัดคะแนนในห้องสอบ:
ห้ามตอบว่า "ย้ายข้อมูลไปเก็บที่ 1000H" หรือ "เขียนลง RAM" โดยเด็ดขาด เพราะ ORG เป็นคำสั่งบอกตัว Assembler ให้เริ่มวางโค้ดลงใน Program ROM ณ ขั้นตอน Assemble เท่านั้น ไม่มีการทำงานใน CPU ขณะ Run-time

ขนาด & รหัสเครื่อง 1 Byte (Opcode: EAH สำหรับ Bank 0 ซึ่งแมปอยู่ที่แอดเดรส RAM 02H)

ผลต่อธงใน PSW ไม่กระทบธง CY, AC, OV (ปรับเฉพาะ Parity Flag P ใน PSW ตามจำนวนเลข 1 ในรีจิสเตอร์ A)

ตำแหน่งในแผนผัง RAM แอดเดรส 35H อยู่ในพื้นที่ User RAM (30H–7FH) ปลอดภัยจากการถูก Stack และ Register Banks เขียนทับ

"A ← A - R1 - Carry" — (ข้อวิเคราะห์: สัญลักษณ์ถูกต้อง แต่ต้องอธิบายให้ชัดว่าทำไมต้องลบ Carry ด้วย)
คำตอบที่ควรเขียนในกระดาษคำตอบห้องสอบ (Exam Answer - ได้คะแนนเต็ม 100%)

คำอธิบายการทำงาน: นำค่าข้อมูลใน Accumulator (A) เป็นตัวตั้ง แล้วลบด้วยค่าข้อมูลในรีจิสเตอร์ R1 และลบด้วยค่าของตัวยืมเดิมที่ค้างอยู่ใน Carry Flag (CY) ผลลัพธ์ที่ได้นำไปเก็บไว้ใน A พร้อมทั้งอัปเดตสถานะของธงต่างๆ ใน PSW (สัญลักษณ์ RTL: A ← A - R1 - CY)

การวิเคราะห์ทางสถาปัตยกรรมและฮาร์ดแวร์เชิงลึก:
โหมดการอ้างแอดเดรส Register Addressing Mode (Subtract with Borrow)
ขนาด & รหัสเครื่อง 1 Byte (Opcode: 99H สำหรับ Register Bank 0)
รอบเวลาทำงาน (Cycles) 1 Machine Cycle (ใช้เวลา $1\ \mu\text{s}$ ที่ความถี่ Crystal $12\text{ MHz}$)
ผลกระทบต่อ PSW Flags
  • CY (Borrow Flag): เซ็ตเป็น 1 หากเกิดการยืมจากบิต 7 (ค่าตัวตั้งน้อยกว่าตัวลบ / ผลลัพธ์ติดลบ)
  • AC (Auxiliary Borrow): เซ็ตเป็น 1 หากเกิดการยืมจากบิต 4
  • OV (Overflow): เซ็ตเป็น 1 หากเกิด Signed Underflow/Overflow ในระบบเลข 2's Complement
ข้อควรระวังและจุดตัดคะแนนในห้องสอบ:
ในไมโครคอนโทรลเลอร์ 8051 ไม่มีคำสั่ง SUB แบบธรรมดา! มีเฉพาะคำสั่ง SUBB (Subtract with Borrow) เท่านั้น ดังนั้นหากต้องการลบเลขธรรมดา 2 ตัวโดยไม่นำตัวทดเดิมที่ค้างอยู่มาลบด้วย วิศวกรต้องสั่ง CLR C (เคลียร์ Carry Flag ให้เป็น 0) ก่อนสั่ง SUBB เสมอ

INC 25H

Direct Addressing Mode (Increment Memory)

แนวทางของรุ่นพี่ (สั้นเกินไป):
"[25H] ← [25H] + 1" — (ข้อวิเคราะห์: ขาดการระบุพื้นที่ RAM และคุณสมบัติพิเศษเรื่อง Carry Flag)
คำตอบที่ควรเขียนในกระดาษคำตอบห้องสอบ (Exam Answer - ได้คะแนนเต็ม 100%)

คำอธิบายการทำงาน: เพิ่มค่าข้อมูลขนาด 8 บิตที่เก็บอยู่ในหน่วยความจำข้อมูลภายใน (Internal Data RAM) ณ ตำแหน่งแอดเดรส 25H ขึ้นอีก 1 ค่า (สัญลักษณ์ RTL: RAM[25H] ← RAM[25H] + 1)

การวิเคราะห์ทางสถาปัตยกรรมและฮาร์ดแวร์เชิงลึก:
โหมดการอ้างแอดเดรส Direct Addressing Mode (ระบุแอดเดรส RAM 25H ตรงๆ)
ขนาด & รหัสเครื่อง 2 Bytes (ไบต์ที่ 1 Opcode: 05H, ไบต์ที่ 2 Direct Address: 25H)
รอบเวลาทำงาน (Cycles) 1 Machine Cycle (ใช้เวลา $1\ \mu\text{s}$ ที่ความถี่ Crystal $12\text{ MHz}$)
ตำแหน่งในแผนผัง RAM แอดเดรส 25H อยู่ในพื้นที่ Bit-Addressable RAM (ช่วง 20H–2FH) ซึ่งมี Bit Address 28H–2FH ฝังอยู่
ผลกระทบต่อ PSW Flags ไม่มีผลกระทบต่อ Carry Flag (CY) โดยเด็ดขาด! (ไม่เปลี่ยนค่า CY แม้จะบวกจนล้น)
ข้อควรระวังและจุดตัดคะแนนในห้องสอบ:
กับดักยอดฮิตของข้อสอบ: คำสั่ง INC และ DEC ใน 8051 จะไม่ส่งผลกระทบต่อ Carry Flag (CY = ไม่เปลี่ยน) แม้ว่าค่าเดิมใน RAM 25H จะเป็น FFH (255) แล้วบวก 1 วนกลับมาเป็น 00H ก็ตาม ค่า CY จะยังคงเป็นค่าเดิม ไม่ถูกเซ็ตเป็น 1!

ANL C, P0.2

Bit Addressing Mode (Boolean Logic AND)
คำสั่งในข้อสอบ:
ANL C, P0.2
แนวทางของรุ่นพี่ (สั้นเกินไป):
"C ← C AND P0.2" — (ข้อวิเคราะห์: สัญลักษณ์ถูกต้อง แต่ควรระบุ Bit Address และบทบาทของ Carry Flag ในฐานะ Boolean Accumulator)
คำตอบที่ควรเขียนในกระดาษคำตอบห้องสอบ (Exam Answer - ได้คะแนนเต็ม 100%)

คำอธิบายการทำงาน: อ่านระดับลอจิกขนาด 1 บิตจากขาพอร์ต 0 บิตที่ 2 (P0.2 ซึ่งอยู่ที่ Bit Address 82H ใน SFR) นำมาดำเนินการทางตรรกะแบบ AND ร่วมกับค่าที่อยู่ใน Carry Flag (C หรือ CY ใน PSW) แล้วนำผลลัพธ์ที่ได้ไปบันทึกเก็บไว้ใน Carry Flag (C) (สัญลักษณ์ RTL: CY ← CY AND P0.2)

การวิเคราะห์ทางสถาปัตยกรรมและฮาร์ดแวร์เชิงลึก:
โหมดการอ้างแอดเดรส Bit Addressing Mode (การควบคุมตัวแปรบูลีนระดับบิตเดี่ยว)
ขนาด & รหัสเครื่อง 2 Bytes (ไบต์ที่ 1 Opcode: 82H, ไบต์ที่ 2 Bit Address: 82H)
รอบเวลาทำงาน (Cycles) 2 Machine Cycles (ใช้เวลา $2\ \mu\text{s}$ ที่ความถี่ Crystal $12\text{ MHz}$)
สถาปัตยกรรม Boolean Processor 8051 มีหน่วยประมวลผลบิตแยกต่างหาก โดยใช้ Carry Flag (C) ทำหน้าที่เป็น Accumulator 1 บิต สำหรับคำนวณลอจิก AND, OR, NOT ระดับบิต
ข้อควรระวังและจุดตัดคะแนนในห้องสอบ:
ปลายทางที่เก็บผลลัพธ์คือ Carry Flag (C) เท่านั้น! ไม่มีการเปลี่ยนแปลงค่าระดับแรงดันที่ขาพอร์ต P0.2 แต่อย่างใด (คำสั่งนี้เป็นการอ่านค่าพอร์ตเข้ามาคำนวณ ไม่ใช่การเขียนทับพอร์ต)

คำสั่งในข้อสอบ:
DJNZ 25H, Label
แนวทางของรุ่นพี่:

คำตอบที่ควรเขียนในกระดาษคำตอบห้องสอบ (Exam Answer - ได้คะแนนเต็ม 100%)

คำอธิบายการทำงาน: ลดค่าข้อมูลในหน่วยความจำข้อมูลภายใน (Internal Data RAM) แอดเดรส 25H ลง 1 ค่า (RAM[25H] ← RAM[25H] - 1) จากนั้นตรวจสอบค่าที่ได้:
• หากค่าหลังลด ยังไม่เท่ากับศูนย์ ($\neq 0$) ให้กระโดด (Jump) ไปทำงานที่ตำแหน่ง Label
• หากค่าหลังลด กลายเป็นศูนย์ ($= 0$) ให้ทำงานต่อไปที่คำสั่งบรรทัดถัดไปตามลำดับปกติ (Fall-through)
(สัญลักษณ์ RTL: RAM[25H] ← RAM[25H] - 1; IF RAM[25H] ≠ 0 THEN PC ← Target ELSE PC ← PC + 3)

การวิเคราะห์ทางสถาปัตยกรรมและฮาร์ดแวร์เชิงลึก:
โหมดการอ้างแอดเดรส Direct Addressing (สำหรับแอดเดรส 25H) ผสมกับ Relative Addressing (สำหรับ Label)
ขนาด & รหัสเครื่อง 3 Bytes (ไบต์ที่ 1 Opcode: D5H, ไบต์ที่ 2 Direct Addr: 25H, ไบต์ที่ 3 Relative Offset: rel)
รอบเวลาทำงาน (Cycles) 2 Machine Cycles (ใช้เวลา $2\ \mu\text{s}$ ที่ความถี่ Crystal $12\text{ MHz}$)
การประยุกต์ใช้งาน เป็นคำสั่งหลักในการสร้าง ตัวนับรอบลูป (Loop Counter) และ ฟังก์ชันหน่วงเวลา (Delay Subroutines)
ข้อควรระวังและจุดตัดคะแนนในห้องสอบ:
อย่าตอบเพียงว่า "ลดค่าแล้วกระโดด" ต้องระบุ เงื่อนไขทั้ง 2 กรณีให้ครบถ้วน: (1) ถ้า $\neq 0$ กระโดดไป Label (2) ถ้า $= 0$ ไม่กระโดดและรันบรรทัดถัดไป และคำสั่งนี้ ไม่มีผลต่อ Carry Flag (CY) เช่นกัน

คำอธิบายการทำงาน: สั่งให้โปรแกรมกระโดดแบบไม่มีเงื่อนไข (Unconditional Short Jump) ไปทำงานยังตำแหน่ง Label โดยใช้วิธีคำนวณแอดเดรสปลายทางแบบสัมพัทธ์ (Relative Addressing) ด้วยค่า Relative Offset ขนาด 8 บิตแบบคิดเครื่องหมาย (Signed 2's Complement ในขอบเขต -128 ถึง +127 ไบต์) นับจากตำแหน่งของคำสั่งถัดไป (สัญลักษณ์ RTL: PC ← PC + 2 + rel)

การวิเคราะห์ทางสถาปัตยกรรมและฮาร์ดแวร์เชิงลึก:
โหมดการอ้างแอดเดรส Relative Addressing Mode (คำนวณระยะทางกระโดดแบบสัมพัทธ์)
ขนาด & รหัสเครื่อง 2 Bytes (ไบต์ที่ 1 Opcode: 80H, ไบต์ที่ 2 Relative Offset: rel 8 บิต)
รอบเวลาทำงาน (Cycles) 2 Machine Cycles (ใช้เวลา $2\ \mu\text{s}$ ที่ความถี่ Crystal $12\text{ MHz}$)
สูตรคำนวณ Offset $\text{Offset} = \text{Target Address} - \text{PC}_{\text{next}}$ โดย $\text{PC}_{\text{next}} = \text{Address ของ SJMP} + 2$
เปรียบเทียบตระกูล Jump
  • SJMP (Short Jump): 2 ไบต์, ขอบเขตแคบ -128 ถึง +127 ไบต์ (Relatively)
  • AJMP (Absolute Jump): 2 ไบต์, กระโดดภายในบล็อก 2 KB Page
  • LJMP (Long Jump): 3 ไบต์, กระโดดได้ทั่วทั้ง 64 KB (0000H–FFFFH)
ข้อควรระวังและจุดตัดคะแนนในห้องสอบ:
ต้องระบุคำว่า "ขอบเขตการกระโดด -128 ถึง +127 ไบต์ (แบบ Signed Two's Complement)" และระบุว่าเป็นการกระโดดนับจาก PC ของคำสั่งถัดไป (ไม่ใช่แอดเดรสของตัว SJMP เอง)
